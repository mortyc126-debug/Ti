# Очередь ИИ-описаний

## Настройка

Перед запуском сервера задайте `MISTRAL_API_KEY` в окружении. Ключ не хранится в библиотеке и не передаётся браузеру. Не добавляйте его в git.

PowerShell:

```powershell
$env:MISTRAL_API_KEY = "ваш-ключ"
node tools/code-lab-server.mjs
```

Linux/macOS:

```sh
MISTRAL_API_KEY="ваш-ключ" node tools/code-lab-server.mjs
```

Необязательная переменная `MISTRAL_MODEL`; по умолчанию используется `mistral-small-latest`.

## API

- `POST /api/describe` — поставить в очередь все куски без описания: `{}`.
- `POST /api/describe` — поставить выбранные куски: `{"ids":["my-piece", "another-piece"]}`.
- `GET /api/jobs` — состояние очереди и последние 100 заданий.

Очередь выполняет по одному запросу за раз. Состояние записывается в `tools/code-lab/data/description-jobs.json`. Задания, которые были `running` во время остановки сервера, возвращаются в `queued` при следующем запуске. Ошибочные задания остаются `failed` и видны в `/api/jobs`; их можно повторно поставить через `POST /api/describe`.

ИИ создаёт `title`, `desc`, `tags`, `aliases`. Код не меняется. Поля с авторством `manual` или `imported` защищены от перезаписи ИИ. Существующее непустое описание без метки авторства также сохраняется.

## Проверка

```sh
node tools/code-lab/tests/describe-queue.test.mjs
```

## Ключ через настройки браузера

В каталоге нажмите «Настройки» и вставьте API-ключ Mistral. Он сохраняется в `localStorage` этого браузера под ключом `codeLab.mistralApiKey`, его можно заменить или удалить там же. При вызовах API ключ передаётся локальному серверу заголовком `X-Mistral-API-Key` и не записывается в файл очереди. Не используйте эту функцию на недоверенных компьютерах: JavaScript страницы может прочитать данные `localStorage`. Для серверного режима по-прежнему можно задавать `MISTRAL_API_KEY` в окружении.

## Управление из веб-каталога

В каталоге доступны кнопки «Описать выбранный» и «Описать все без описания». Ключ задаётся через «Настройки» и хранится в `localStorage` текущего браузера. При запуске описания и проверке состояния очереди браузер передаёт ключ локальному серверу в заголовке `x-mistral-api-key`; ключ не передаётся в URL и не записывается в файл состояния очереди.

Статус очереди обновляется автоматически примерно раз в 2,5 секунды. На карточках без описания отображается отметка «нужно описание». Ошибки отдельных заданий доступны в ответе `GET /api/jobs` в поле `jobs[].error`.

## ИИ-дополнение разделов куска

На странице куска (`component.html`) у разделов есть кнопки «✨»: **описание** (① Что делает), **пояснения** (② к строкам и словам кода), **требования** (③), **можно/нельзя** и **ошибки** (④). Во вкладке «Разобраться» конструктора есть «✨ дополнить через ИИ» для описания узла.

Порядок: кнопка → (необязательное пожелание: «проще», «добавь пример») → «предложить» → правишь текст → «применить». Пока не нажато «применить», ничего не пишется. Уже написанное тобой передаётся модели как «сохрани и дополни»; пояснения к строкам/словам, которые у тебя уже есть, не перезаписываются. Код куска не меняется.

- `POST /api/ai-complete` — `{ id | piece:{title,lang,code,desc}, section, instruction }` → `{ current, suggestion }`, ничего не сохраняет. Ключ — заголовок `x-mistral-api-key` (или `MISTRAL_API_KEY` на сервере).
- `POST /api/ai-apply` — `{ id, section, value }` → записывает принятое. `section`: `desc | notes | requirements | limits | errors`.

Тест: `node tools/code-lab/tests/ai-assist.test.mjs`.

## Создание новых кусков через ИИ

В каталоге кнопка **«✦ Создать куски через ИИ»**: выбираешь язык (JS, TS, Python, CSS, HTML, SVG, JSON, SQL, Bash, PowerShell, Go, Ruby, PHP, Lua, R, Perl; рядом показано, сколько кусков уже есть), пишешь тему («работа со строками», «JOIN между таблицами») и сколько кусков нужно (1–8). ИИ получает названия уже имеющихся кусков этого языка и не должен их повторять.

Предложения показываются карточками: название, раздел, описание и код можно править; галочкой отмечаешь нужные. Помечаются дубли (то же название или тот же код) и результат проверки синтаксиса. Проверка **без запуска**: JS только компилируется, JSON разбирается, для остальных языков написано «не проверялся». В библиотеку попадает только то, что отмечено и нажато «добавить отмеченные». Созданные куски получают пометку `generated.by = ai` и статусы `not_verified` / `not_run`. Куски без описания можно сразу отдать «Описать все без описания».

- `GET /api/ai-langs` — языки и количество кусков в каждом.
- `POST /api/ai-gaps` — `{ lang }` → `{ topics:[{topic, why}] }`: «что тут не хватает?». Необязательная опция: в окне создания кнопка «🔍 что тут не хватает?» просит ИИ предложить темы-пробелы, клик по теме добавляет её в поле «что дополнить». ИИ видит только названия и разделы кусков, не код, поэтому тема может оказаться уже закрытой под другим названием — смотрите на дубли в карточках. Ничего не сохраняет.
- `POST /api/ai-generate` — `{ lang, topic, count, instruction }` → `{ pieces:[…] }`, ничего не сохраняет.
- `POST /api/ai-create` — `{ pieces:[{title,lang,group,desc,output,tags,aliases,code}] }` → `{ created, skipped }`. Дубли по коду и неизвестные языки пропускаются.

Тест: `node tools/code-lab/tests/ai-generate.test.mjs`.
