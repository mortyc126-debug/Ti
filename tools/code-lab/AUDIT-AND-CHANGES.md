# CodeForge — заметки к доработке

## Что изменено
- В инспекторе конструктора теперь всегда виден контракт блока: что он получает, что выдаёт, что нужно подготовить и какие ограничения проверить.
- Для основных блоков JavaScript добавлены предметные требования и типовые ошибки.
- Добавлены предварительные проверки для `map`/`filter`/`reduce`, формул и вывода в консоль: предупреждения указывают на вероятно не объявленные переменные.
- В карточках каталога пустые сведения о требованиях и зависимостях больше не трактуются как «ничего не нужно». Интерфейс прямо сообщает, что сведения не описаны.
- Во все 138 JSON-шаблонов добавлены базовые метаданные компонента: назначение, среда, вход/выход, требования, шаги применения и проверки. Где сведения выведены эвристически, это не означает, что код проверен.
- Статусы проверки оставлены `not_verified` / `not_run`: автоматическое добавление описаний не является тестированием кода.

## Важные ограничения архива
В архиве есть `public/` и `templates/`, но нет серверного кода, `package.json` или инструкции запуска. Поэтому нельзя проверить обработчики `/api/list`, `/api/template`, `/api/add` и `/api/delete` целиком и нельзя честно заявить, что весь проект запущен end-to-end. Эти изменения проверены статически: JavaScript-файлы проходят `node --check`, JSON-шаблоны разбираются без ошибок.

## Что стоит делать следующим этапом
1. Сделать отдельную схему контракта компонента (`input`, `output`, `requirements`, `dependencies`, `effects`, `risk`, `verification`) и проверять её при сохранении.
2. Различать «выведено анализатором», «подтверждено статически» и «проверено запуском».
3. Добавить проверку связей компонентов: наличие входной переменной, DOM-узла, среды исполнения, async-контекста и зависимости.
4. Перевести рисование SVG из сборки строк через `innerHTML` на безопасное создание узлов либо жёстко валидировать координаты.
5. Исправить запуск асинхронного кода в предпросмотре: ошибки Promise/fetch сейчас могут не попасть в журнал, если они возникают после синхронного `try/catch`.
6. Добавить тесты для API и сценарии браузерного тестирования.


## Следующий этап: самопроверяющиеся компоненты
- Добавлен формальный контракт блока: тип входа/выхода, поле связи, DOM-требования и async-контекст.
- Связи теперь проверяются до создания: несовместимый тип или источник без результата не соединяются; совместимая связь автоматически подставляет имя результата в поле входа.
- В инспекторе показываются проверки именно текущего узла и его входящих связей.
- Предпросмотр теперь ловит `error`, `unhandledrejection` и отклонение верхнего async-контекста, поэтому ошибки `fetch()`/Promise не теряются после синхронного `try/catch`.
- SVG больше не строится через `innerHTML`: точки разбираются как числа, а `svg`/`polyline` создаются через `createElementNS` и `setAttribute`.
- Блок `bars` теперь принимает как список чисел, так и массив-переменную, что делает связь `массив → столбики` фактически полезной.
- Статусы по-прежнему означают «проверено локальным анализатором», а не полноценный end-to-end тест сервера: серверная часть в исходном архиве отсутствует.

## Этап 1 — исправление проверки контрактов
- Исправлены регулярные выражения в `constructor.js`: ранее в исходнике оставались экранированные `\\b`/`\\w`, из-за чего объявления и идентификаторы не распознавались как задумано.
- Проверка идентификаторов переведена на Unicode property escapes (`ID_Start`/`ID_Continue`), поэтому русские и другие Unicode-имена переменных теперь анализируются корректно.
- Проверка совместимости типов перенесена перед проверкой DOM-зависимости: наличие `#c`/`#out` больше не может скрыть несовместимость типов.
- Повторно выполнена синтаксическая проверка `constructor.js` и отдельная проверка распознавания Unicode-объявлений/идентификаторов.

## Этап 2 — строгий контракт связей

Сделано:
- добавлена статическая типизация результата простых выражений (`array`, `object`, `string`, `number`, `boolean`, `function`);
- совместимость теперь проверяет фактический тип простого результата, а не пропускает любой `any` в конкретный вход;
- `array → map/filter/reduce/bars` разрешается, `number → bars` и `object → map` блокируются;
- Unicode-идентификаторы используются в единой проверке имён переменных;
- проверка объявлений строит таблицу символов до текущего блока, поэтому текущий блок не может сам «объявить» вход, который ему нужен;
- инспектор показывает подходящие типы блоков для текущего результата;
- добавлены автоматические Node-тесты `tests/constructor-contracts.test.js`.

## Этап 3 — runtime-проверка окружения

Дата: 2026-10-17

Сделано:

- после запуска preview фактически проверяется наличие найденных DOM-селекторов в документе iframe;

Дата: 2026-10-17

- При сохранении компонента в каталог обнаруженные зависимости сохраняются в `summary.dependencies` вместе с источником/блоком-поставщиком.
- Для шаблонов SheetJS и Zustand явно записаны зависимости и источник в метаданных.
- Добавлены Node-тесты обнаружения зависимостей и различения доступной, отсутствующей и ESM-зависимости.

## Этап 5 — самопроверка перед сохранением компонента
Дата: 2026-10-17

Сделано:
- Перед сохранением компонента выполняется отдельный preflight `componentPreflight()`.
- Проверяется непустой код и синтаксис JavaScript; для кода с `await` используется async-обёртка при синтаксическом анализе.
- Проверяется обязательный вход текущего блока и наличие именованной входной переменной в коде компонента.
- Повторно проверяются все входящие и исходящие связи выбранного блока; несовместимая связь блокирует сохранение.
- Неподдерживаемая ESM/npm-зависимость блокирует сохранение; зарегистрированная browser-script зависимость без загруженного глобала показывается как предупреждение, потому что Preview умеет подключить её автоматически.
- DOM-требования сверяются со стандартным preview-окружением (`#c`, `#out`, `#log`); неизвестные обязательные селекторы становятся предупреждением и требуют отдельной настройки окружения.
- Для `calc` отдельно проверяются переменные, используемые в формуле.
- Внешние runtime-идентификаторы не скрываются: они явно показываются как предупреждения.
- В окне сохранения появился видимый отчёт: `готово`, `есть предупреждения` или `сохранение заблокировано`.
- Кнопка сохранения отключается, пока есть ошибки preflight.
- Перед фактическим POST выполняется повторный preflight, поэтому обход блокировки только через состояние UI невозможен.
- Добавлен `tests/save-preflight.test.js`.
