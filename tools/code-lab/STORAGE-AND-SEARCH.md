# Хранение и поиск

## Где что лежит

```
tools/code-lab/
  library/                     ← куски кода (создаётся при первом запуске)
    css/жирный-mv6cut1.css            обычный текст, открывается чем угодно
    css/жирный-mv6cut1.css.meta.json  описание, раздел, теги, пояснения слов
    js/…  python/…  sql/…  html/…
    _synonyms.json                    синонимы для поиска (правятся руками)
  templates/                   ← старые карточки; больше не читаются и не меняются (резервная копия)
  lib/                         ← модули: токенайзер, хранилище, поиск
  tests/                       ← тесты
```

**Код — источник правды.** Подсветка и пояснения слов строятся из текста при каждой загрузке.
Правите файл в любом редакторе — лаборатория подхватывает изменение в течение секунды.

**Положили файл в `library/` руками** (без `.meta.json`) — он появится в списке со статусом
`needs_description`; метафайл создастся при первом сохранении из интерфейса.

**Первый запуск** сам переносит `templates/*.json` в `library/`. Вручную то же делает
`node tools/migrate-templates.mjs` (есть `--dry` и `--force`).

## Метафайл

```json
{
  "id": "css-bold", "title": "жирный", "lang": "css", "group": "CSS: текст и шрифты / Начертание",
  "desc": "…", "output": "…",
  "tags": [], "aliases": [],
  "source": { "title": "imported", "desc": "manual", "tags": null },
  "status": "described",
  "wordNotes": [ { "line": 0, "col": 4, "text": "font-weight", "note": "…", "source": "dict|custom" } ],
  "orphanNotes": [ … ]
}
```

* `source.*` — кто автор поля: `manual` (вы), `imported` (архив, старые шаблоны), `ai` (модель).
  Правило на будущее: `manual` ИИ не перезаписывает.
* `wordNotes` привязаны к позиции слова. После правки кода пояснение встаёт на то же слово,
  даже если оно сместилось. Слово пропало — пояснение уходит в `orphanNotes` и вернётся, когда слово появится.
* Пояснения из словаря `keyword-dict.json` подставляются при загрузке там, где своего пояснения нет.
  Если стереть пояснение (пустая строка), словарь его не вернёт.

## Поиск

`GET /api/search?q=толщина букв&limit=60` →
`{ hits: [{ id, score, why: [{ q, kind, via, found, in }] }], total, terms }`

Ищет по названию, описанию, тегам, синонимам куска, разделу, пояснениям слов и **по самому коду**.
Понимает словоформы (толщина/толщину), `font-weight` целиком и по частям, `querySelector` как
`query` + `selector`, начало слова, одну опечатку. Всё, что находил прежний поиск по подстроке,
находится по-прежнему.

Синонимы — `library/_synonyms.json`: группы слов, которые вы считаете одним и тем же.
Добавили группу `["бордюр", "border", "рамка"]` — поиск подхватит без перезапуска.

сделанные после перехода, лежат только в `library/`.

## Загрузка пачки кусков (txt)

`POST /api/ingest` с телом `{ "text": "...", "dry": true }` (`dry` — только показать, что получится;
необязательные `lang` и `group` — значения по умолчанию).

```
=== жирный | css | CSS: текст и шрифты
описание: делает буквы жирными
теги: шрифт, толщина
.b { font-weight: 700; }

=== Клик по кнопке
document.querySelector('button').addEventListener('click', () => console.log(1));
```

* `=== Название | язык | раздел` — язык и раздел можно опустить; язык тогда определяется по коду.
* Сразу под разделителем — необязательные пометки: `описание:`, `теги:`, `синонимы:`, `раздел:`, `язык:`, `вывод:`.
* Подходят и блоки в тройных обратных кавычках (название — строка перед блоком).
* Тот же код, что уже есть в библиотеке, пропускается как дубль (ничего не перезаписывается).
* Всё, что вы написали в пометках, получает автора `manual`; куски без описания помечаются `needs_description`
  (позже их закроет ИИ). Ответ содержит список `items` и `warnings`.

Пример: `curl -X POST localhost:PORT/api/ingest -d @body.json`.
