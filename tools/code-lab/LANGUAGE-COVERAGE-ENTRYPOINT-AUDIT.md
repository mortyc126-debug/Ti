## 2. SQL: базовые запросы есть, но язык не обеспечен собственным словарём пояснений

### Фактическое содержание

15 файлов состоят из:
- базовой выборки и фильтрации: SELECT, WHERE, ORDER BY, LIMIT, DISTINCT, LIKE;
- группировок и агрегатов: GROUP BY, HAVING, COUNT, SUM, AVG;
- соединения таблиц через JOIN ... ON;
- изменения строк: INSERT, UPDATE, DELETE;
- обработки NULL и COALESCE.

Встречаются подготовительные CREATE TABLE и INSERT, но это не отдельная серия по проектированию схем. Самостоятельных учебных сценариев для транзакций, COMMIT/ROLLBACK, ограничений целостности, индексов, CTE, подзапросов и оконных функций нет.

### Подтверждённые проблемы пояснений

В паспортах SQL встречаются пояснения из JavaScript и других контекстов:
- `VALUES` объясняется как `Object.values`;
- `FROM` — как часть JS import;
- `JOIN` — как склеивание массива в строку;
- `DELETE` — как удаление свойства объекта;
- `DEFAULT` — как значение по умолчанию в export/switch/параметрах;
- `NULL` — через JavaScript null.

Примеры проверены в:
- `library/sql/join-соединить-две-таблицы-mvds0h4r.sql.meta.json`;
- `library/sql/select-where-order-by-выбрать-и-отсортир-mvds0h5n.sql.meta.json`;
- `library/sql/insert-update-delete-менять-данные-mvds0h3u.sql.meta.json`;
- `library/sql/null-и-coalesce-пустые-значения-mvds0h69.sql.meta.json`;
- `library/sql/удалить-строки-mvh8him7.sql.meta.json`.

В `public/dict/langs` нет отдельного `sql.json`. В `code-names.mjs` словарные имена для языка берутся из `dict.langs[L]` вместе с общими `dict.words`; при отсутствии SQL-файла SQL-специфичные ключи не имеют собственного словарного источника. Это согласуется с обнаруженными устаревшими/чужими пояснениями в сохранённых паспортах.

### Ошибка метаданных отдельной карточки

`library/sql/same-mean-sql.sql.meta.json`:
- код действительно SQL и файл имеет `lang: sql`;
- группа ошибочно указана как «Числа и математика / Арифметика и округление»;
- runtime указан как JavaScript;
- `component.subcat` содержит подозрительное значение «Числа и просты».

Основная категория должна отражать SQL-запросы/агрегатные функции. Исправление пока не вносилось.

### Вывод по SQL

Проблема двойная:
1. Реальное тематическое покрытие ограничено базовыми запросами и DML.
2. Пояснения токенов загрязнены межъязыковыми значениями, а собственного SQL-словаря в языковой папке нет.

Нельзя исправить это только добавлением новых SQL-фрагментов: сначала нужно восстановить правильный источник терминологических пояснений и перепроверить сохранённые wordNotes.

## 3. TypeScript: шесть utility types, отдельного словаря нет, есть смешение с JavaScript

### Фактическое содержание шести .ts-файлов

Все шесть исходников — небольшая подборка служебных типов:
- Pick;
- Omit;
- Readonly;
- Partial;
- Record;
- Parameters.

Это целостная подборка по utility types, но не покрытие языка. Отдельных материалов по базовым типам и интерфейсам, union/intersection, narrowing, generics, type guards, discriminated unions, перегрузкам, модулям и настройке компилятора нет.

### Подтверждённая конфигурация словарей и обработчиков

В репозитории есть языковые словари CSS, HTML, JS и Python. Отдельного `ts.json` нет; в базовом `keyword-dict.json` языковой раздел `ts` также отсутствует.

При этом:
- `typescript` канонизируется в `ts`;
- `tokenizer.mjs` включает ts в семейство JS-подобных языков, но отдельного набора `KW.ts` нет — используется запасной `KW.js`;
- `code-names.mjs` явно преобразует `ts` в `js` для анализа имён и использует JS-словарь;
- запуск TypeScript предусмотрен через `npx tsx`.

Следовательно, запуск TypeScript предусмотрен, но отдельный словарный и лексический контекст языка не оформлен. JS fallback может быть полезен для общей части синтаксиса, но не заменяет объяснения TypeScript-специфичных конструкций.

### Два TypeScript-связанных файла вне каталога ts

В каталоге JS обнаружены:
- `поле_через_параметр_конструктора_в_typescript.js` — содержит настоящий TypeScript-синтаксис параметров конструктора (`private readonly имя: string`), но паспорт имеет `lang: js` и расширение `.js`. Это подтверждённое несоответствие языка и расширения содержимому.
- `строгие-проверки-typescript-mvr81m2n.js` и `строгие_проверки_typescript.js` — два файла с одинаковым кодом объекта настроек `compilerOptions.strict`. Это пример конфигурационного объекта, а не демонстрация TypeScript-проверки компилятором. Их нельзя считать двумя разными примерами TypeScript.

### Вывод по TypeScript

Сейчас есть:
- 6 корректно размещённых карточек utility types;
- 1 TypeScript-фрагмент с неправильными языком и расширением;
- 2 одноимённых по смыслу одинаковых JS-фрагмента конфигурации strict;
- рабочая привязка запуска через tsx;
- отсутствие отдельного словаря TS и самостоятельного покрытия базового языка.

Перед расширением библиотеки нужно решить не «добавить ещё файлов», а сначала оформить TS как язык в словарной и поисковой инфраструктуре, затем развести учебные примеры языка и справочные примеры конфигурации.

## 4. Bash / Shell: карточки командной строки, а не учебные примеры Bash

Все 32 файла просмотрены. Содержимое — одиночные команды или короткие команды с комментарием:
- npm / npx: установка пакетов, запуск скриптов, сборка, тесты, аудит зависимостей, форматирование, проверка типов;
- Node.js CLI: запуск с отладчиком, source maps, watch, env-file, трассировка, проверка синтаксиса;
- команды тестового раннера Node.js.

В исходниках нет самостоятельных Bash-конструкций:
- объявления и подстановки переменных;
- позиционных аргументов;
- if/case и циклов;
- функций;
- конвейеров и перенаправлений;
- кодов завершения и обработки ошибок;
- массивов, globbing, trap и работы с сигналами.

Эти карточки полезны как справочник команд проекта. Но расширение `.sh` и `lang: sh` создают видимость учебного покрытия Bash, которого по содержимому нет.

### Ошибка контекста в паспортах

В проверенных паспортах команд Node.js встречается требование «нужны Node.js и установленный prettier» и шаги про форматирование, в том числе у карточек запуска встроенного тестового раннера и запуска с отладчиком. Для этих команд Prettier не является требованием. Это похоже на ошибочное копирование общего шаблона паспорта.

### Вывод по Bash

Не удалять и не переписывать существующие команды. Их следует учитывать как «Командная строка / Node.js и npm». Сам Bash пока считать фактически не покрытым. Для учебного раздела нужны отдельные сценарии shell, а не переименование npm-команд.

## 6. Адресный план исправлений — без автоматического выполнения

### Приоритет 1: корректность пояснений
1. Добавить отдельный SQL-словарь с описаниями SQL-операторов и функций.
2. Добавить отдельный TS-словарь для ключевых слов, модификаторов, utility types и конструкций типов.
3. Проверить, что аннотатор и интерфейс действительно выбирают языковой словарь, а не только общий `words`.
4. Пересобрать/проверить сохранённые wordNotes SQL и TS по исходному коду; пользовательские заметки не перезаписывать.
5. Добавить регрессионные тесты на конфликтующие имена: SQL FROM/JOIN/VALUES/DELETE/NULL против JS import/Array.join/Object.values/delete/null.

### Приоритет 2: корректная языковая принадлежность
1. Исправить язык и расширение TypeScript-кода в `поле_через_параметр_конструктора_в_typescript.js` после проверки всех ссылок и запуска.
2. Развести карточки конфигурации TypeScript и учебные примеры языка.
3. Проверить и уточнить паспортные требования Bash/CLI-команд: удалять Prettier из требований там, где он не нужен.
4. Оставить npm/Node.js команды в библиотеке, но не считать их покрытием Bash.

### Приоритет 3: реальное тематическое покрытие
1. SQL: транзакции, ограничения и индексы, подзапросы/CTE, оконные функции, разные виды JOIN, изменение схемы и миграции.
2. TypeScript: базовые типы/интерфейсы, union/intersection, narrowing, generics, type guards, async-типы, модули и конфигурация.
3. Bash: переменные, аргументы, условия, циклы, функции, конвейеры, перенаправления, коды завершения и безопасная обработка ошибок.

Не создавать отдельный файл на каждый пункт автоматически: сначала проверить существующие фрагменты других языков, словари, aliases, связи и поисковые фразы. Одну конструкцию можно связать с несколькими релевантными темами без копирования исходника.
