# Аудит двух систем синонимов

Статус: read-only инвентаризация на 2026-11-06. Ни один словарь не изменён.

## Краткий результат

В проекте две разные по смыслу системы:

1. public/dict/synonyms.json — ключ словаря → фразы, которыми пользователь может описать смысл ключа. Это не строгий список синонимов: в значениях есть вопросы, описания поведения, примеры, названия ошибок и формулировки задач.
2. library/_synonyms.json — группы слов, которые полнотекстовый поиск считает взаимозаменяемыми и использует для расширения запроса. Именно эта система напрямую влияет на смешение результатов.

library/_synonyms.json и lib/default-synonyms.json полностью совпадают побайтно. Файл по умолчанию не является отдельной актуальной редакцией.

## 1. Словарь фраз для терминов

Файл: public/dict/synonyms.json

- 1 707 ключей;
- 11 629 фраз в значениях;
- 10 855 уникальных нормализованных фраз;
- 675 фраз используются у нескольких разных ключей;
- максимальная неоднозначность одной фразы — 6 ключей;
- 60 фраз одновременно являются ключами словаря и значениями у других ключей;
- некорректных типов данных и повторяющихся нормализованных ключей не найдено.

Примеры неоднозначности:

| Фраза | Ключи, к которым она привязана |
|---|---|
| значение по умолчанию | def f(a, b=0) ..., default, dict.get(k, default), getattr(a, "x", d), x = a or b |
| длина | .length, len, len(x) |
| метод класса | @classmethod, classmethod(f), cls, def m(self ...) |
| обработка ошибок | try, try ... except ..., try/catch |
| записать в файл | open, open(path, mode, encoding), write |

Это не обязательно ошибки словаря. Одна и та же формулировка может быть полезным поисковым запросом для нескольких примеров. Но переносить такие значения в aliases пользовательских конструкций нельзя: тогда неоднозначные запросы станут утверждением о тождестве понятий.

Есть и 60 пересечений между ключами и значениями. Например, throw — самостоятельный ключ, но одновременно значение у raise; string — ключ и формулировка для str. Такие пересечения требуют сохранения направления «ключ → фраза», а не превращения в двустороннюю синонимию.

## 2. Группы полнотекстового поиска

Файл: library/_synonyms.json

- 102 группы;
- 567 элементов;
- пустых групп и повторов внутри одной группы нет;
- 4 нормализованных термина встречаются в разных группах: float, var, подмена, join.

Пересечение групп имеет практический эффект: поисковый запрос по такому термину расширяется сразу через несколько тематических наборов. Например, float может одновременно вести к CSS-обтеканию и числовому типу; var — к объявлению переменной и финансовой дисперсии/риску.

### Группы, где смешаны разные понятия

Ниже не предлагается удалять слова. Это примеры, где текущая модель «все элементы одной группы равнозначны» слишком груба.

| Текущая группа | Почему нельзя считать все элементы синонимами |
|---|---|
| отступ / padding / margin | padding и margin — разные стороны блочной модели |
| рамка / border / outline | border участвует в размерах элемента, outline — отдельный контур |
| позиция / position / absolute / relative / fixed / sticky | свойство, понятие расположения и разные значения свойства |
| объект / словарь / object / dict / map / ключ | объект, словарь, Map и ключ — не одно понятие |
| событие / click / keydown / обработчик / listener | событие, тип события, обработчик и подписчик — разные сущности |
| элемент / блок / контейнер / div / DOM / узел / тег / querySelector | элемент, узел, тег, контейнер и функция поиска элемента связаны, но не эквивалентны |
| ошибка / исключение / try / catch / throw | ошибка/исключение — объект или ситуация, try/catch/throw — управляющие конструкции |
| файл / читать / записать / open / read / write | объект работы и операции над ним |
| разделить / split / склеить / join | противоположные операции |
| копия / copy / clone / spread / slice / structuredClone | разные способы и глубина копирования |
| риск / волатильность / дисперсия / var | риск — более широкое понятие; волатильность и дисперсия не тождественны |
| корреляция / ковариация / связь | корреляция и ковариация — разные метрики |

Такие группы объясняют, почему поиск может возвращать тематически близкий, но неправильный фрагмент.

## 3. Что сохранять раздельно

Для будущей модели нужны разные отношения:

- exact — точная запись/обозначение;
- alias — другое название того же понятия;
- form — вариант синтаксиса или записи;
- related — тематически связанное понятие;
- part-of / contains — часть и целое;
- requires / depends — зависимость;
- example — пример применения;
- query-phrase — формулировка, по которой ищут понятие, но которая не объявляется синонимом.

Старые фразы из public/dict/synonyms.json в большинстве случаев нужно сохранять как query-phrase с исходным ключом и provenance. Переносить в alias можно только после подтверждения эквивалентности.

Группы из library/_synonyms.json нельзя механически разложить на пары: сначала надо разделить каждую группу на смысловые подгруппы и направленные отношения. До завершения этой работы старый поиск должен оставаться неизменным.

Первичная ручная разметка 17 наиболее рискованных групп с индексами и предлагаемым разделением вынесена в [SYNONYM-GROUP-TRIAGE.md](SYNONYM-GROUP-TRIAGE.md). Это предложения для проверки, не миграция.

## 4. Безопасный план

1. Оставить оба legacy-файла без изменений.
2. Сформировать таблицу «исходный ключ/группа → предложенный тип → объяснение → уверенность».
3. Сначала разобрать самые широкие и явно смешанные группы: события, DOM, объекты/словари, ошибки, операции с файлами, копирование, CSS-геометрия.
4. Отдельно отметить неоднозначные фразы из словаря, не превращая их в эквиваленты.
5. Сверить предложения с уже созданными пользовательскими понятиями.
6. Подготовить dry-run нового индекса и сравнить выдачу на контрольных запросах.
7. Переключать общий поиск только после сравнения результатов и наличия отката.

**Вывод:** public/dict/synonyms.json — в первую очередь словарь пользовательских формулировок для поиска по терминам; library/_synonyms.json — механизм расширения полнотекстового поиска, который сейчас смешивает синонимы с родственными понятиями. Их нельзя объединять или мигрировать одной операцией.
