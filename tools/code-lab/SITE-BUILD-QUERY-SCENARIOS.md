# Сценарии проверки: от обычного запроса до сайта

Это отдельный контрольный набор для классификации и интерфейса поиска. Он не является списком синонимов: каждая задача должна раскладываться на несколько типов конструкций и объяснять, почему они связаны.

## 1. Кнопка с действием

**Запрос:** «Добавить кнопку, которая по нажатию показывает сообщение».

Ожидаемая цепочка:
- HTML: `button`, назначение `type="button"`, текст кнопки.
- JavaScript: событие `click`, подписка через `addEventListener`, функция/обработчик.
- DOM: связь между кнопкой и действием; селектор по `id` или `data-*` с объяснением различий.
- CSS: оформление кнопки — отдельная необязательная ветка, не обязательное условие её работы.

Не считать эквивалентами: `click` (само событие/метод) и `addEventListener` (подписка); `type="submit"` и `type="button"`.

## 2. Ссылка и переход

**Запрос:** «Сделать надпись ссылкой на другую страницу».

Ожидаемая цепочка:
- HTML: `a` и обязательный `href`.
- Атрибуты: `target` и `rel` только при необходимости и с объяснением.
- CSS: состояния ссылки и оформление — отдельно от назначения перехода.

Не подменять ссылку кнопкой: у ссылки переход, у кнопки действие.

## 3. Сворачиваемый блок

**Запрос:** «Сделать блок, который можно раскрыть и свернуть».

Ожидаемая цепочка:
- Нативный вариант: `details` + `summary`; объяснить, что `summary` — заголовок/переключатель и должен быть первым внутри `details`.
- Управляемый вариант: кнопка + JS-состояние + `hidden`/обновление `aria-expanded`; показать, когда нужен контроль над поведением.
- CSS: вид закрытого/открытого состояния — только оформление.

Не выдавать `display: none`, `visibility: hidden`, `overflow: hidden` и `.reduce()` как взаимозаменяемые способы свернуть интерфейс.

## 4. Подсветка заголовка при наведении

**Запрос:** «Подсветить надпись в шапке, когда на неё наводят курсор».

Ожидаемая цепочка:
- HTML: выбрать сам заголовок/ссылку в шапке (`header` — область, а не обязательно конкретная надпись).
- CSS: селектор конкретного элемента + `:hover`.
- CSS-свойство: выбрать подходящее визуальное изменение (например, `color`, `background-color`, `text-decoration`, `text-shadow`) по желаемому эффекту.
- Опционально: `:focus-visible` для клавиатурного управления.

Не считать `:hover` свойством оформления; это условие/состояние селектора. Не считать `header` и заголовок `h1/h2` одним и тем же.

## 5. Данные из нескольких источников в разных местах страницы

**Запрос:** «Получить данные из двух источников и показать имя в шапке, список в основном блоке, итог внизу».

Ожидаемая цепочка:
- JavaScript: сетевой запрос (`fetch`), ожидание (`await`), разбор ответа (`response.json()`).
- Данные: различить источник, ответ, объект/массив и поля.
- DOM: отдельные точки вывода и выбор элементов (`querySelector`/селекторы).
- Преобразование: сопоставление/объединение данных, фильтрация или вычисление итога — только если задача этого требует.
- Отображение: заполнение нескольких элементов страницы; обработка загрузки и ошибки.

Не смешивать HTTP-запрос, API, ответ, DOM-элемент и данные. Не предлагать `Promise`, `fetch`, `JSON.parse` как синонимы.

## 6. Сворачивание страницы/разделов

**Запрос:** «Сделать так, чтобы можно было свернуть длинную часть страницы».

Сначала определить масштаб:
- один блок/раздел;
- боковая панель/навигация;
- все содержимое страницы;
- только визуальное переполнение с прокруткой.

Подбор решения должен зависеть от масштаба. Не предлагать `overflow: hidden` без пояснения, что оно обрезает содержимое и само по себе не создаёт переключатель.

## Критерии оценки каждого сценария

1. Запрос понимается без знания английского названия конструкции.
2. Система выделяет объект, действие, условие, оформление, данные и связи, если они присутствуют.
3. Точные конструкции идут выше связанных, но неравнозначных.
4. Каждая связь имеет тип и объяснение: «внутри», «после», «содержит», «требует», «значения», «связывает», «пример».
5. Пользователь видит минимальный рабочий вариант и альтернативу, когда есть разные способы.
6. Указано, что обязательно, что необязательно и при каких условиях выбирать альтернативу.
7. Пример можно собрать в работающий фрагмент; не остаётся списка несвязанных английских терминов.

## Проверки ввода

Для каждого запроса проверить:
- ввод всей фразы целиком, включая фразы длиннее четырёх слов;
- ввод с курсором в середине фразы;
- ввод с клавиатуры, вставкой и экранной/IME-клавиатурой;
- отсутствие запроса на каждый символ, если он не нужен;
- возможность вызвать поиск явно;
- сохранение полного запроса при открытии панели;
- одинаково понятное поведение в inline-подсказках и отдельном поиске дерева.

## Запреты на ложную классификацию

- Не создавать отдельную категорию для пользовательских конструкций: найденные языковые элементы показывать в их обычных разделах.
- Синоним не является доказательством синтаксической связи.
- Совпадение префикса имени не является доказательством вложенности.
- CSS-состояние/селектор не является CSS-свойством.
- HTML-область (`header`) не тождественна заголовку (`h1`–`h6`).
- Событие не тождественно обработчику; запрос не тождественен API; данные не тождественны месту их отображения.
