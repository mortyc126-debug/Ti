# Контрольный набор запросов для нового поиска

Назначение: сравнить текущую выдачу и будущий параллельный индекс. Набор фиксирует не только ожидаемые совпадения, но и результаты, которые нельзя подтягивать как эквивалентные. Это спецификация проверки, не изменение поиска.

## Правила оценки

- **Точно**: ожидаемый термин/конструкция должен быть в верхней части выдачи.
- **Связано**: допустимо ниже точных совпадений или при включённом поиске связанных понятий.
- **Не подмешивать**: результат не должен появляться только из-за ошибочной синонимии.
- Для многозначных слов обязательны контекст языка/раздела либо явное предупреждение о неоднозначности.
- Старый поиск оставить контрольной базой; новый индекс запускать параллельно, не заменяя его.

## Неоднозначные короткие запросы

| Запрос | Ожидаемое поведение |
|---|---|
| float | показать неоднозначность или запросить/использовать контекст CSS против языка программирования |
| var | различить объявление переменной и variance; финансовый раздел не должен появляться в кодовом контексте |
| join | различить строковый join и объединение коллекций по типу данных/языку |
| подмена | различить replace и тестовые mock/patch/stub по контексту |
| размер | не выдавать нерелевантные типы размеров без объекта; уточнить или ранжировать по точным полям |
| найти | не допускать бесконтекстного размножения методов поиска, оставлять точные результаты выше связанных |
| скрыть | различать CSS visibility/display, атрибут hidden и методы конкретных API |

## Метрики сравнения

Для каждого запроса фиксировать:
1. наличие точного ожидаемого результата в top-5 и top-10;
2. позицию первого точного результата;
3. число ложных эквивалентов в top-10;
4. число результатов, добавленных только расширением отношений;
5. корректность объяснения «почему найдено»;
6. изменение относительно legacy-выдачи.

Критерий переключения: не ухудшить top-5 точных результатов на базовых запросах; убрать ложные эквиваленты в перечисленных отрицательных примерах; не терять полезные query-phrase, а переносить их в отдельный слой поиска с сохранением происхождения.

## Что этот набор пока не покрывает

Нужны реальные запросы из истории использования, реальные фрагменты библиотеки и ручная оценка релевантности. Этот набор — стартовый регрессионный каркас, а не доказательство качества нового поиска.
