# Интеллектуальные подсказки и проверка CSS в песочнице

Статус: проект требований для следующего этапа редактора. Это не отметка о реализованной функциональности.

## Цель

Сделать написание кода быстрым, но не превращать подсказки в непрозрачный список английских идентификаторов. Пользователь должен за короткий ввод находить конструкцию, понимать её смысл, видеть более короткие/развёрнутые формы и получать объяснение ошибок.

## Что уже есть и чего не хватает

- В песочнице CodeMirror подключён с `hint/anyword-hint`: Ctrl-Space вызывает подбор слов, но это не языковой CSS-парсер и не знает смысл свойств.
- `sel-explain.js` уже умеет показывать пояснение выделенного фрагмента.
- CSS-словарь содержит 36 общих свойств и 23 значения в `keyword-dict.json`, а `dict/langs/css.json` содержит примеры и фрагменты. Эти источники нельзя считать полной моделью CSS.
- Отдельные примеры кратких форм уже встречаются в CSS-словаре, но связь «сокращённое свойство ↔ исходные свойства» не хранится как структурированные данные.
- `code-check.js` проверяет общие скобки/кавычки; предметной проверки CSS-свойств, значений и контекста раскладки пока нет.

## 1. Контекстное автодополнение

Подсказки должны появляться после первого символа, когда это не создаёт шум, и обновляться по мере ввода.

Контекст определяется по позиции курсора:
- внутри имени свойства до двоеточия — предлагать свойства;
- после двоеточия — значения именно текущего свойства;
- внутри функции (например `calc(`, `rgb(`, `var(`) — аргументы/значения этой функции;
- после селектора и до блока — селекторы/псевдоклассы/атрибуты, а не CSS-свойства;
- внутри строки и комментария — не запускать обычное автодополнение кода.

Результат каждой подсказки содержит:
- написание;
- короткое русское назначение;
- тип записи: свойство, значение, функция, селектор, краткая форма;
- применимость и важные ограничения;
- признак рекомендованного варианта;
- при наличии — связь с другими формами записи.

Порядок ранжирования:
1. точное совпадение с контекстом и префиксом;
2. краткая форма, если она действительно заменяет нужный набор свойств без изменения смысла;
3. часто используемые и совместимые варианты;
4. остальные совпадения.
Не поднимать краткую форму выше, если она неприменима к текущей раскладке или не сохраняет заданные значения.

## 2. Структурированные связи кратких и развёрнутых форм

Связи хранить отдельно от текстовых пояснений. Минимальная запись:
- идентификатор краткого свойства;
- список составляющих свойств в точном порядке CSS-спецификации;
- правила разложения одного/двух значений;
- область применимости;
- исключения и примечания;
- дата/версия источника сведений.

Начальные группы:
- `place-items` → `align-items`, `justify-items`;
- `place-content` → `align-content`, `justify-content`;
- `place-self` → `align-self`, `justify-self`.

Для `place-items`: первое значение относится к `align-items`, второе — к `justify-items`; одно значение применяется к обеим составляющим. Для остальных кратких форм порядок также задаётся явно, а не выводится из имени.

Нужны две операции:
- «Свернуть»: преобразовать совместимые пары отдельных свойств в краткую запись;
- «Развернуть»: заменить краткую запись составляющими свойствами, сохранив значения и порядок.

Перед преобразованием проверить, что:
- обе составляющие присутствуют и совместимы;
- нет конфликтующих повторных объявлений и комментариев, которые потеряются;
- преобразование не меняет каскад/порядок применения;
- shorthand не сбрасывает дополнительные longhand-свойства, которые пользователь явно задавал.

Нельзя автоматически сворачивать только по совпадению значений: у CSS shorthand могут быть побочные эффекты сброса других составляющих. Если безопасность преобразования не доказана, показать аналог, но не предлагать автоматическую замену как гарантированно эквивалентную.

## 3. Пояснение выделенного текста

Для выделенного CSS-имени или декларации показывать компактную карточку:
- что делает;
- к какой оси/области относится;
- где работает (Grid, Flexbox, block layout и т. п.);
- допустимые значения с пояснениями;
- краткая форма и развёрнутые аналоги;
- типичные ошибки;
- пример до/после.

Если выделена декларация целиком, анализировать свойство вместе со значением. Если выделено только имя, объяснять свойство и показывать варианты записи. Не заменять существующую функцию объяснения — расширить её.

## 4. Контекстная проверка CSS

Проверка должна разделять ошибки и предупреждения:
- ошибка: неизвестное свойство (с учётом vendor-prefix/custom properties), синтаксически недопустимое значение, незакрытая конструкция;
- предупреждение: свойство не действует в данном типе раскладки, значение допустимо, но, вероятно, не даёт ожидаемого результата;
- рекомендация: можно использовать более короткую/понятную форму, но это не ошибка.

Учитывать зависимости:
- `align-items` и `justify-items` имеют разную применимость;
- `justify-content` и `align-content` зависят от типа раскладки и свободного пространства;
- `place-items` задаёт обе составляющие, но `justify-items` не выравнивает flex-элементы так, как пользователь может ожидать;
- оси нельзя всегда подписывать просто как «горизонталь» и «вертикаль»: они зависят от writing-mode и flex-direction. В интерфейсе сначала показывать «главная/поперечная» или «строчная/блочная ось», а горизонталь/вертикаль указывать как типичный случай.

Не выдавать эвристическую проверку как полную валидацию CSS. В перспективе подключить CSS parser/validator и проверять реальные декларации/селекторы, а не регулярные выражения по строкам.

## 5. Управление формой записи

Пользователь управляет предпочтением:
- краткие формы в приоритете;
- развёрнутые формы в приоритете;
- не менять автоматически, только показывать аналоги.

По умолчанию: краткие формы в приоритете в списке подсказок, но код автоматически не переписывать. Любое сворачивание/разворачивание — явное действие с предварительным просмотром результата и возможностью отмены.

## 6. Этапы реализации

1. Инвентаризировать CSS-словарь и существующие подсказки; не смешивать свойства, значения и сниппеты.
2. Создать структурированный реестр CSS-свойств, значений, кратких форм и контекстных ограничений.
3. Написать независимый тестируемый CSS-context resolver: позиция курсора → тип ожидаемого токена → список кандидатов.
4. Подключить собственный CodeMirror hint provider вместо общего anyword для CSS; сохранить anyword как запасной режим для остальных языков.
5. Расширить карточку выделения аналогами и переключением форм.
6. Добавить CSS-диагностику и тесты на реальные фрагменты из библиотеки.
7. Провести browser-smoke: ввод с одного символа, выбор подсказки, Tab/Enter, отмена, выделение декларации, сворачивание/разворачивание, сообщения об ошибках.

## Критерии приёмки

- В CSS-файле по первому символу появляются релевантные свойства, а не случайные слова из всего документа.
- После двоеточия предлагаются значения текущего свойства.
- У каждой подсказки есть понятное русское назначение.
- Для трёх групп place-* отображаются корректные пары и порядок значений.
- Сворачивание/разворачивание сохраняет смысл и не теряет комментарии/порядок каскада; сомнительные случаи блокируются.
- Выделение свойства показывает аналоги и ограничения.
- Ошибки и рекомендации различаются визуально и по тексту.
- Для HTML/JS/Python/SQL текущая логика автодополнения не ломается.

### Дополнение — shorthand/longhand и объяснение выделения

Реализован начальный реестр `public/css-shorthands.js`:
- `place-items` → `align-items`, `justify-items`;
- `place-content` → `align-content`, `justify-content`;
- `place-self` → `align-self`, `justify-self`.

Порядок значений зафиксирован явно. Одно значение расширяется на обе составляющие, два распределяются по заданному порядку. Сворачивание блокируется, пока вызывающая сторона не подтвердит сохранение комментариев, отсутствие дублей, сохранение каскада, проверку сброса дополнительных свойств и грамматики.

`sel-explain.js` использует реестр при разборе выделенного CSS-имени: shorthand показывает составляющие, longhand — связанный shorthand. Это пока объяснение связи, а не интерактивная кнопка преобразования деклараций.

Тесты:
- `tests/css-shorthands.test.mjs` — порядок, расширение, поиск обратной связи и блокировки небезопасного сворачивания;
- `tests/browser-smoke.mjs` — объяснение `place-items` показывает обе составляющие;
- GitHub Actions run `42537768273`: Ubuntu, Windows и browser-smoke — success.

Следующее действие: построить безопасный предварительный просмотр сворачивания/разворачивания на диапазоне CSS-кода. Не менять исходный текст до явного подтверждения и проверки каскада.


### Предпросмотр развёрнутой формы

Панель объяснения выделенного полного объявления теперь показывает развёрнутый вариант для простых значений `place-items`, `place-content` и `place-self`. Предпросмотр использует порядок из реестра и не меняет исходный код. Для сложных или неоднозначных значений он намеренно не появляется.

Browser-smoke проверяет, что выделение `place-items: center;` показывает `align-items: center;` и `justify-items: center;`. Коммит `aa43e6c97804ebeb455331ea9bec76a512033661`, run `42538134614`: Ubuntu, Windows и browser-smoke — success.

Ограничение: это только просмотр развёрнутого аналога. Применение преобразования к редактору и обратное сворачивание пары longhand пока не подключены. Следующий шаг — анализ диапазона одного CSS-правила и безопасный preview для обратного преобразования; вставка возможна только после явного подтверждения.


## 8. Дополнение к реализации — обратный предпросмотр (2026-11-09)

Добавлен предварительный обратный путь для трёх зарегистрированных пар:
- `align-items` + `justify-items` → `place-items`;
- `align-content` + `justify-content` → `place-content`;
- `align-self` + `justify-self` → `place-self`.

Предпросмотр доступен только для выделенной пары соседних деклараций внутри одного блока. Проверяются порядок компонентов, точный диапазон исходного текста, повторные объявления, уже существующий shorthand и ограниченный набор значений для каждого longhand. Комментарии в выбранном диапазоне и неподдерживаемые/неоднозначные случаи не преобразуются.

Предпросмотр не изменяет редактор. Применение преобразования, обратное действие через undo и полноценная CSS-грамматика ещё не реализованы. Ограниченный список значений намеренно консервативен и не является полной CSS-валидацией.

Добавлены unit- и browser-smoke проверки отказа для дублирующего объявления и значения, недопустимого для соответствующего longhand. Результат CI для последних коммитов ожидает подтверждения; не считать этот этап закрытым до успешного прогона Ubuntu, Windows и browser-smoke.
