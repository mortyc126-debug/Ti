# Первый аудит теневого поиска поисковых фраз

Дата: 2026-11-06  
Ветка: `audit/fixes-2026-11-06`

## Объём проверки

Проверен исходный `public/dict/synonyms.json` без записи в него и без изменения рабочего индекса.

- 1 707 ключей-целей;
- 11 629 направленных фраз;
- 67 запросов из контрольного набора;
- 28 запросов дали хотя бы одну цель;
- 39 запросов не дали совпадений;
- 18 запросов дали несколько ключей-целей.

Это проверка слоя поисковых фраз по нормализованному точному совпадению, началу или вхождению строки. Она **не является полной оценкой top-5/top-10**: здесь ещё не учитывались ранжирование фрагментов, словоформы и реальная релевантность содержимого куска. Для этого предназначен HTTP endpoint `/api/search/shadow`.

## Запросы без совпадений

- JavaScript/Python: объявить переменную; объявить константу; функция с именем; пройти по массиву; условие иначе; список Python; словарь Python; разбить строку по разделителю; соединить элементы массива в строку; найти элемент массива; проверить наличие элемента; округлить до двух знаков; асинхронно дождаться результата; сериализовать в JSON.
- DOM/сеть/файлы/тесты: подписаться на клик; запросить данные по HTTP; тестовая заглушка; подменить функцию в тесте; подготовка перед тестом; очистка после теста.
- Финансовые термины: волатильность актива; дисперсия доходности; корреляция двух рядов; ковариация двух рядов; доходность облигации; эмитент облигации.

Вывод: старый словарь не покрывает значительную часть контрольных формулировок. Это не повод автоматически дописывать их в legacy-словарь: новые формулировки должны добавляться отдельно, с источником и назначением.

## Неоднозначные и подозрительные результаты

| Запрос | Полученные цели | Замечание |
|---|---|---|
| стрелочная функция | `lambda`, `lambda x` | Python lambda не тождественна JS arrow function |
| ключ словаря | `__hash__(self)`, `del`, `frozenset`, `frozenset(it)`, `hash(...)`, `typeerror unhashable` | несколько разных аспектов работы ключей; не одно понятие |
| найти элемент по id | `document.getelementbyid`, `id` | `id` — атрибут/идентификатор, не операция поиска |

### Подтверждённые ошибки и исправления

- `стрелочная функция` → Python `lambda`: удалена ошибочная пара. Python lambda не является синтаксическим эквивалентом JS arrow function.
- `найти элемент по id` → `id`: удалена ошибочная пара. Атрибут `id` не является операцией поиска.
- `join` → `set.isdisjoint`: устранено совпадение по подстроке внутри слова `disjoint`.
- `скрыть элемент` → любые фрагменты с `display`: оставлены только фрагменты с `display: none`; `display: grid` и другие режимы раскладки исключены.
- `скрыть но оставить место` → `visibility`: оставлены только фрагменты с `visibility: hidden`.
- `ограничить ширину` → `max-width`: исключены совпадения с условием медиазапроса `(max-width: ...)`; оставлены CSS-декларации свойства `max-width:`.
- `открыть файл` → `open` и `with`: исключены JavaScript-вызовы IndexedDB и контекстные менеджеры, не открывающие файлы; проверяются язык и фактический синтаксис открытия файла.
- `число с плавающей точкой` → `float`: CSS-свойство `float` исключено, остаются Python-фрагменты.
- `поверхностная копия`: вызовы `pandas.DataFrame.copy()` больше не выдаются как `copy.copy()` или копирование словаря.
- Цели, к которым не привязан ни один реальный фрагмент библиотеки, исключены из выдачи.

### Ранжирование и сравнение позиций

Теневой слой теперь возвращает отдельный список `rankedPieces`. Он ранжирует фрагменты по совпадению целевой фразы и релевантности названия, описания, тегов и aliases. Это детерминированная эвристика, не семантическая модель; score нового и старого поиска напрямую сравнивать нельзя.

- 73 позиции фрагментов получены в shadow top-10 по 67 запросам.
- 25 из этих 73 фрагментных результатов также присутствовали в legacy top-10; их средняя позиция в legacy — 4,0, в shadow — 3,52. Выборка пересечения мала и не доказывает общее превосходство нового ранжирования.
- 48 результатов shadow не встретились в legacy top-10; это кандидаты на дополнительную ручную проверку, а не автоматически подтверждённые улучшения.
- Варианты сигнатуры одной функции (`copy.deepcopy(obj)` и `copy.deepcopy(x)`) больше не считаются разными понятиями. После этого единственный запрос с несколькими понятиями — `открыть файл` (разные действия `open` и `with`).

Запросы, где shadow сохранил кандидатов: размер шрифта; межстрочный интервал; ограничить ширину; число с плавающей точкой; строка; глубокая копия; поверхностная копия; округлить вниз; обработать исключение; выбросить исключение; прочитать файл; открыть файл.

### Ограничения, которые остаются

- Для 55 из 67 формулировок shadow не нашёл направленной фразы после консервативной фильтрации. В этих случаях остаётся доступна прежняя выдача; новый слой её не заменяет.
- Однословные общие запросы (`float`, `var`, `join`, `размер`, `найти`, `скрыть`) намеренно не расширяются по началу или подстроке. Для них нужен отдельный контекстный поиск, а не автоматическое размножение синонимов.
- Позиции shadow основаны на эвристике по метаданным и ключу в коде. Результаты с низкой metadata relevance могут содержать нужный токен в коде, но не быть лучшим учебным примером.
- Рабочий `/api/search` не переключался. Словари и содержимое пользовательской библиотеки не переписывались.

Полный машинный отчёт создаётся в CI как `query-phrase-audit.json` в артефактах `code-lab-library-audit-ubuntu-latest` и `code-lab-library-audit-windows-latest`.
