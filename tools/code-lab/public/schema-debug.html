Отладка — как ловить баги

Подробная схема одного слоя: инструменты, приёмы и живые примеры «найди баг». Нажимай «запустить» — увидишь, как баг себя проявляет.

0Главная мысль

Баг — это всегда неверное предположение где-то в коде. Ты думала «здесь лежит число», а там строка. «Здесь массив непустой», а он пустой. Отладка = найти место, где реальность разошлась с твоим ожиданием. Не «тупить в код», а сужать, где именно.

1Читать ошибку (а не бояться её)

Красный текст — это не ругань, а карта. Главное в ней: что случилось и где (файл + строка). Читай снизу вверх в Python, сверху вниз смысл — одинаков.

Traceback (most recent call last):
  File "strategy.py", line 42, in compute      # ← ГДЕ: файл и строка
    avg = total / len(prices)
ZeroDivisionError: division by zero              # ← ЧТО: делили на ноль
Читается так: «на строке 42 файла strategy.py при делении случилось деление на ноль». Значит len(prices) был 0 → список цен пустой. Баг не в делении — выше, там, где prices должен был наполниться. Ошибка показала симптом, причину ищешь против течения.

2Инструменты

самый частый

print / console.log

Впечатай значение в подозрительном месте: print("prices:", prices). Грубо, но мгновенно видно, где значение уже не то. 80% багов ловят этим.

точнее

debugger / breakpoint

Ставишь точку останова — код замирает на строке, и ты смотришь ВСЕ переменные в этот момент. В Python: breakpoint(). В браузере: F12 → Sources → клик по номеру строки.

браузер

DevTools (F12)

Console — ошибки и логи. Network — что запросил и что вернулось (статус, тело). Sources — точки останова. Твой друг №1 при «данные не пришли».

страховка

assert

«Падай сразу, если невозможное»: assert 0 <= p <= 1. Лучше громкий сбой в нужном месте, чем тихо неверный результат через 1000 строк.

по-взрослому

logging (а не print)

Логи с уровнями: debug / info / warning / error. Можно включать/выключать, писать в файл с временем. print — для разовой охоты, logging — навсегда.

по истории

git bisect

«Вчера работало, сегодня нет». git сам половинит историю коммитов и находит тот, что сломал. Не гадаешь — находишь виновный коммит за минуты.

3Приёмы (как сужать)

Минимальное воспроизведение

Выкинь всё лишнее, оставь крошечный кусок, где баг ещё есть. Часто в процессе сам понимаешь причину.

Деление пополам

Баг где-то в 500 строках? Проверь значение в середине. Верно — баг во второй половине, нет — в первой. 500 → 250 → 125… 9 шагов на тысячу строк.

Проверь вход и выход функции

Функция врёт? Напечатай, что в неё ВОШЛО и что ВЫШЛО. Часто вход уже битый — тогда беда у того, кто вызвал, а не здесь.

Резиновая уточка

Объясни код вслух (хоть утке). На фразе «а здесь он берёт…» часто сам слышишь, где соврал. Серьёзный приём, не шутка.

3.5Виды багов — пощупай каждый

Узнавать баг в лицо — половина дела. Нажми «запустить» у каждого: увидишь, КАК он проявляется. Симптом подсказывает категорию, категория — где искать.

Логическая ошибка

Код работает, не падает — но считает НЕ ТО. Самая коварная. Тут цикл по границам съехал.

const n = [10, 20, 30];
let s = 0;
for(let i = 1; i <= n.length; i++) s += n[i]; // i: 1,2,3 — мимо!
console.log("среднее:", s / n.length);

Выйдет NaN: пропустили n[0], залезли в n[3]=undefined. Симптом «NaN/не то число» → ищи логику и границы.

Краевой случай

Работает на обычных данных, ломается на пустом/нуле/одном элементе.

const пусто = [];
console.log("сумма:", пусто.reduce((a,b)=>a+b)); // reduce без старта на []

Упадёт: Reduce of empty array with no initial value. Симптом «падает только иногда» → проверь пустые/крайние входы (дай reduce((a,b)=>a+b, 0)).

Баг типов

Ждал число — пришла строка (из поля/сети). JS молча склеивает.

const a = "5";   // строка
console.log("склеил:", a + 3, " сложил:", Number(a) + 3);

склеил: "53" сложил: 8. Симптом «числа слипаются / NaN при математике» → приводи типы (Number(x)).

Состояние / общая ссылка

Думал, скопировал — а это та же коробка. Меняешь одну — «само» меняется в другой.

const a = [1, 2];
const b = a;        // НЕ копия — та же ссылка
b.push(3);
console.log("a:", a.join(","), " b:", b.join(","));

a: 1,2,3 b: 1,2,3 — изменились оба! Симптом «данные меняются сами» → ищи общие ссылки (копируй: [...a]).

Проглоченная ошибка

Ошибка была — но её поймали и выкинули. Код едет дальше как ни в чём.

try { null.foo; } catch(e) { /* тишина */ }
console.log("дошли сюда — а ошибку не видели");

Видишь только последнюю строку. Ошибка null.foo была, но исчезла. Симптом «ничего не падает, но результат пустой» → ищи except/catch без лога.

Синтаксис

Самый лёгкий: код вообще не запускается, движок ругается сразу и показывает строку.

console.log("забыл скобку"     // ← нет )

Увидишь SyntaxError с местом. Хорошая новость: такой баг виден сразу, в отличие от логического.

4Твоя боль: проглоченная ошибка

293 места с except: pass / catch(){}. Ошибка случается — и её молча хоронят. Самый злой вид бага: ничего не падает, просто результат неверный, а следов нет. Нажми обе кнопки — почувствуй разницу.

🔴 глотаем ошибку

function среднее(nums){
  try {
    return nums.reduce((a,b)=>a+b)/nums.length;
  } catch(e){ /* тишина */ }
}
console.log("итог:", среднее(null)); // null вместо массива

Видишь: итог: undefined. Что сломалось — непонятно. Так баг и прячется месяцами.

🟢 ловим и показываем

function среднее(nums){
  if(!Array.isArray(nums) || !nums.length)
    throw new Error("нужен непустой массив, пришло: "+nums);
  return nums.reduce((a,b)=>a+b)/nums.length;
}
try{ console.log(среднее(null)); }
catch(e){ console.log("⛔", e.message); }

Теперь: ⛔ нужен непустой массив, пришло: null. Сразу видно ЧТО и откуда. Вот разница между «молчит» и «говорит».

Правило: лови конкретную проблему и сообщай о ней (лог/throw). except: pass оправдан редко — когда сбой правда не важен (один битый ИНН из тысячи) И ты это осознанно решил. 293 раза «не важно» — это не решение, это привычка прятать.

5Найди баг сам (живые примеры)

Запусти — увидишь неверный результат. Попробуй понять, где соврало, прежде чем читать подсказку.

Пример 1 — считает среднее трёх чисел

const nums = [10, 20, 30];
let сумма = 0;
for(let i = 1; i <= nums.length; i++)   // ← что-то с границами…
  сумма += nums[i];
console.log("сумма:", сумма, " среднее:", сумма/nums.length);
подсказка / ответ

Выйдет NaN. Краевой баг индекса: массив из 3 элементов имеет индексы 0,1,2. А цикл идёт i=1..3: пропускает nums[0] и лезет в nums[3] = undefined. Правильно: for(let i=0; i < nums.length; i++). Классика «с нуля и строго меньше длины».

Пример 2 — складывает проценты

const a = "5";   // пришло из поля ввода — это СТРОКА
const b = 3;
console.log("сумма:", a + b);
подсказка / ответ

Выйдет "53", а не 8. Баг типов: "5" + 3 — JS видит строку слева и склеивает, а не складывает. Лечится приведением: Number(a) + b. Это та самая ловушка данных из полей/сети — всегда приводи к числу.

6Способы — в виде команд

«Проверить» или «логировать» — это не абстракция, а конкретные команды. Вот чем именно это делают, слева Python, справа JS/браузер.

7Словарь (разбор твоих строк)

Двести девяносто три раза — pass. / Я ставлю print в центральный класс. / Проверка? Нет данных и трассировки стэка. / Где-то проглочен exception… Все фикстуры зелёные, coverage — в потолок, / А в проде опять отвалился поток. / Mock возвращает идеальный ответ. / Реальный источник — None и привет. Кэш протух, но считается свежим, / У объекта потерян контекст. / Я ставлю логгер — баг стал вежливым, / И ушёл в асинхронный процесс.

По каждому слову: что это, откуда берётся и какие есть альтернативы.

pass (в except)

откуда: Python требует непустое тело у блока; pass — «ничего не делать»

Заглушка, превращающая «поймал ошибку» в «молча проглотил». Альтернатива: ловить конкретный тип (except ValueError) и логировать (logging.exception), либо не ловить вовсе — пусть падает там, где сломалось.

print в центральный класс

откуда: встроенная функция вывода

Быстрая разовая охота: воткнул — посмотрел — убрал. Альтернатива: logging (включается/выключается, пишет время и уровень, в файл), breakpoint/pdb (видишь все переменные сразу, а не по одной).

трассировка стэка (stacktrace)

откуда: интерпретатор строит её в момент исключения

Цепочка вызовов до места падения — «кто кого звал». Главная улика. Если её нет (проглотили) — верни: не глотай, или traceback.print_exc() / e.stack. Нет стека = работаешь вслепую (ровно твоя строка).

exception (исключение)

откуда: raise или ошибка рантайма (деление на ноль, None.foo…)

Объект-сигнал «что-то не так», прерывает поток и летит вверх, пока кто-то не поймает. Альтернатива перехвату: try/except конкретного типа; в других стилях — коды возврата / Result-объекты вместо исключений.

фикстуры (fixtures)

откуда: тест-фреймворк, напр. @pytest.fixture

Готовый «стенд» для теста: подготовленные данные/окружение (фейковый портфель, временная база). Ловушка: фикстура — это твоё представление о данных, а не реальность. Зелёные фикстуры ≠ рабочий прод (см. Mock/None ниже).

coverage (покрытие)

откуда: coverage.py / pytest --cov

Процент строк кода, которые прогнали тесты. Обман метрики: 100% ≠ 0 багов — строку выполнили, но не проверили на правильном входе. «Coverage в потолок» и падающий прод — классика. Лечение: тесты на краевые случаи, не на количество строк.

Mock (мок)

откуда: unittest.mock — поддельный объект вместо настоящего

Подменяет реальную биржу/сеть заготовленным ответом, чтобы тест был быстрым и без интернета. Ровно твоя строка: mock отдаёт идеал, а живой источник — None → тест зелёный, прод падает. Лечение: интеграционные/контрактные тесты + тест именно на None/пустой ответ.

None (null / undefined в JS)

откуда: функция ничего не вернула, ключа нет, данные не пришли

«Пусто». Беда: None.foo → падение, или тихо течёт дальше как «ничего». Защита: ранняя проверка if x is None, значения по умолчанию, Optional-типы, «ранний возврат» при пустом входе.

протухший кэш (stale cache)

откуда: кэшируем ради скорости (у тебя — heavy-cache раз в 5 баров)

Сохранённый старый результат, который код считает свежим. Показывает вчерашнее как сегодняшнее. Лечение: TTL (срок годности), инвалидация по ключу/версии, cache-busting ?_t=timestamp (это уже есть в твоём прокси ГИР БО).

потерян контекст

откуда: колбэки, async, передача метода «без привязки»

Код выполняется не в той обстановке: потерян this/self, замыкание поймало не ту переменную, объект уже изменился. Лечение: стрелочные функции (сохраняют this), bind, functools.partial, явно передавать состояние, а не надеяться на окружение.

логгер

откуда: logging (py) / console+библиотеки (js)

Запись событий с уровнями (debug/info/warning/error), временем, назначением (экран/файл). Управляемый, в отличие от print. Твоя ирония точна: логгер показал ошибку, но не починил — «баг стал вежливым»: теперь он сообщает о себе и спокойно едет дальше.

асинхронный процесс

откуда: сеть, таймеры, параллелизм (await, колбэки, очереди, отдельный поток)

Код выполняется «не сразу», а по готовности/параллельно. Почему баги там злее: порядок недетерминирован, стектрейс рвётся на await (не видно, кто звал), воспроизвести трудно. Способы: async-debug режим, логи с таймстемпом и id задачи, console.trace(), делать тесты детерминированными.

Отладка — навык, а не талант. Метод один и тот же: сузить место → проверить предположение → починить причину → закрыть тестом.
