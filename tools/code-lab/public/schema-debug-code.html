1. Исключение и трассировка стэка — как читать

в коде
def mean(prices):
    return sum(prices) / len(prices)   # prices пустой → len=0
mean([])
команда — просто запусти, Python сам покажет
python strat.py
вывод
Traceback (most recent call last):
  File "strat.py", line 3, in <module>
    mean([])
  File "strat.py", line 2, in mean
    return sum(prices) / len(prices)
ZeroDivisionError: division by zero
как толковать: читай снизу вверх. Низ — что (ZeroDivisionError = делили на ноль). Выше — где (строка 2 в mean). Ещё выше — кто позвал (строка 3). Значит чинить не деление, а откуда пришёл пустой список.
альтернатива — поймать и залогировать (не глотать)
import logging
try:
    mean([])
except ZeroDivisionError:
    logging.exception("mean упал")   # пишет ERROR + весь стек
как толковать: logging.exception даст строку ERROR:root:mean упал и тот же стек — но в лог, с временем. Отличие от except: pass: там было бы пусто, тут видно что и где.

2. None / undefined — как поймать «пусто»

в коде (JS)
const data = cache.get("bonds");   // вернул undefined — ключа нет
console.log("длина:", data.length);  // 💥
команда — напечатать тип и значение ПЕРЕД использованием
const data = undefined;
console.log("тип:", typeof data, "| значение:", data);
как толковать: выведет тип: undefined | значение: undefined → данных нет вообще (ключа не было). Если бы было тип: object | значение: null — пусто намеренно. А тип: string на том, что ждал массив — баг типов. Тип подсказывает причину.
альтернатива — ранняя проверка / assert
if(data == null) throw new Error("нет данных по bonds");
// Python: assert data is not None, "нет данных"
как толковать: упадёт с понятным сообщением ровно там, где пусто, а не через 500 строк на загадочном .length of undefined.

3. print vs logging — и что значит вывод

print (Python)
print("score:", 0.14)
# вывод: score: 0.14        # голый текст, без контекста
logging — тот же факт, но с уровнем и источником
import logging
logging.basicConfig(level=logging.DEBUG)
logging.info("score: %s", 0.14)
# вывод: INFO:root:score: 0.14
как толковать вывод лога INFO:root:score: 0.14 — три части: INFO уровень важности · root какой логгер (обычно имя модуля) · дальше сообщение. Уровни по росту: DEBUG < INFO < WARNING < ERROR. Поставил level=WARNING — DEBUG и INFO молчат, видно только проблемы. Так глушат шум, не стирая строки.
массив/таблицу — console.table
console.table([{имя:"ОФЗ",ytm:16.1},{имя:"ВДО",ytm:24.3}]);
как толковать: в настоящем DevTools console.table рисует данные сеткой — сразу видно кривую строку среди сотни. (В нашей мини-песочнице таблицы нет, но в F12 попробуй.)

4. assert — поймать невозможное

в коде
function проверь(p){
  console.assert(p >= 0 && p <= 1, "вероятность вне [0,1]: " + p);
  return p;
}
проверь(1.7);   // вероятность не может быть 1.7
как толковать: увидишь Assertion failed: вероятность вне [0,1]: 1.7. Это сигнал «сюда дошло то, чего быть не должно». В JS console.assert только пишет и не останавливает. В Python assert p<=1 — падает с AssertionError. Ставь на входах функций и инвариантах («сумма весов = 1»), чтобы ловить гниль у истока.

5. Потерян контекст (this) — увидеть и починить

в коде — метод передали как колбэк, this потерялся
const счётчик = {
  n: 0,
  плюс(){ this.n++; console.log("n =", this.n); }
};
setTimeout(счётчик.плюс, 0);   // this уже НЕ счётчик
как толковать: выведет this есть? false — внутри this уже не объект (потерян при передаче). Симптом: «метод работает при прямом вызове и ломается в колбэке/таймере».
лечение — стрелка (сохраняет this) или bind
setTimeout(() => счётчик.плюс(), 0);   // стрелка держит контекст
setTimeout(счётчик.плюс.bind(счётчик), 0); // или явно привязать
как толковать: теперь this снова указывает на объект. Правило: передаёшь метод «на потом» — оборачивай в стрелку или bind.

6. Тесты, coverage, mock — как читать отчёт

команда
pytest -q                 # прогнать тесты
вывод
..F..                              # 5 тестов: . прошёл, F провалился
FAILED test_risk.py::test_sortino - assert 1.8 == 2.0
3 passed, 1 failed, 1 ... in 0.4s
как толковать: точка = тест прошёл, F = упал (assert не сошёлся), E = ошибка ещё до проверки (код сломался). Строка FAILED … говорит где и что ждали vs получили (1.8 == 2.0).
покрытие — какие строки НЕ проверены
pytest --cov --cov-report term-missing
Name          Stmts   Miss  Cover   Missing
risk.py         120     18    85%   44-51, 90
                         ↑            ↑
                не проверено 18    номера строк
как толковать: Cover 85% — проверено 85% строк. Missing 44-51, 90 — вот эти строки тесты ни разу не прогнали (часто там и прячется баг). Гонись не за 100%, а за покрытием краевых случаев.
ловушка mock: тест с mock.return_value = {...идеал...} проверяет твою фантазию, не биржу. Зелёный тест + падающий прод = mock врёт, а живой источник отдал None. Лечение: отдельный тест, где mock возвращает None/мусор — переживёт ли код?

7. Протухший кэш — как уличить

команда — логируй ВОЗРАСТ кэша при чтении
age = time.time() - cached_at
logging.debug("cache age = %.0fs (ttl=%d)", age, TTL)
как толковать: в логе cache age = 920s (ttl=300) → возраст 920с при сроке 300с = отдаёшь протухшее как свежее. Вот и объяснение «данные не обновляются».
лечение — срок годности и cache-busting
if age > TTL: data = refetch()        # протухло → перечитать
url += "?_t=" + Date.now()            # обойти кэш запроса (как в твоём прокси)

8. Асинхронный баг — почему стек «рвётся» и что делать

в коде
async function main(){
  const d = await load();   // если load упадёт — стек укажет сюда, а не на исток
  show(d);
}
команда — логируй с ID задачи и временем
console.log(`[${Date.now()}] task#${id} → load start`);
console.trace("кто меня звал");   # печатает цепочку вызовов
как толковать: по таймстемпам видно реальный порядок (а он в async не такой, как в коде сверху вниз). По task#id не путаешь, чей это лог, когда их десять параллельно. console.trace() дорисовывает цепочку, которую await обычно обрывает.

9. «Вчера работало» — git bisect

команды
git bisect start
git bisect bad                 # сейчас сломано
git bisect good a1b2c3d        # этот коммит точно работал
# git прыгает в середину — ты проверяешь, говоришь:
git bisect good   |   git bisect bad
# …повторяешь, пока не сойдётся
git bisect reset               # выйти
как толковать итог: git напишет a9f0e1 is the first bad commit — вот коммит, который всё сломал. Открываешь его diff — обычно там 5 строк, и причина налицо. 1000 коммитов проверяются за ~10 шагов (половинит).

Главный навык — не запомнить команды, а читать вывод: тип значения, уровень лога, строка стека, номер непокрытой строки, таймстемп. Вывод всегда отвечает на «что и где», а «почему» ты достраиваешь против течения.
