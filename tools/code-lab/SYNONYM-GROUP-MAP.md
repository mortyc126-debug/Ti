# Рабочая разметка групп legacy-поиска

Статус: аналитическая карта, не миграция. Источник — `library/_synonyms.json`; номера групп — индексы массива с нуля. 17 наиболее рискованных групп разобраны отдельно в `SYNONYM-GROUP-TRIAGE.md`; ниже — остальные 85 групп. Старые словари не менялись.

## Типы отношений

- **alias** — другое название того же понятия.
- **form** — вариант синтаксической или текстовой записи.
- **related** — связано по теме, но не равно.
- **query-phrase** — формулировка пользовательского поиска, не утверждение о тождестве.
- **part-of / contains / requires / example / opposite** — типизированная связь между разными сущностями.

Уверенность показывает уверенность в предлагаемом разделении. Средняя означает, что нужно проверить контекст языка/API или реальные фрагменты.

## Межгрупповые пересечения

| Термин | Группы | Как разрешать |
|---|---|---|
| float | 27, 45 | CSS-обтекание против числового типа; контекст CSS/Python/JS |
| var | 38, 95 | объявление переменной против финансовой дисперсии/риска |
| подмена | 53, 101 | операция замены против тестовой техники |
| join | 54, 90 | разбиение/соединение строк против объединения структур; контекст типа данных |

## Ограничения и следующий шаг

1. Это карта отношений, а не список готовых эквивалентов. Не переносить все термины в `aliases`.
2. Текущая модель пользовательских понятий умеет хранить aliases, forms и типизированные связи, но не имеет отдельного хранилища `query-phrase` с provenance и контекстом языка. Это нужно решить до миграции.
3. Для неоднозначных терминов сохранить исходную группу, язык/контекст и объяснение; не расширять поиск без контекста.
4. До переключения поиска собрать контрольные запросы для смешанных групп и сравнить выдачу параллельного индекса с legacy.
5. Не менять `library/_synonyms.json` и `lib/default-synonyms.json` до завершения dry-run и проверки отката.
