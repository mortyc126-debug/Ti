## Цель

Пользователь начинает с намерения: «сделать кнопку», «свернуть блок», «подсветить заголовок при наведении», «получить данные из нескольких источников и разместить их в разных частях страницы». Поиск должен привести к правильным конструкциям HTML, CSS, JavaScript и к связям между ними, объяснить назначение и показать подходящие фрагменты. Классификация при этом остаётся обычной языковой: HTML, CSS, JavaScript, Python и их разделы. Отдельная категория «пользовательские конструкции» не вводится.

## 1. Единый парсер структурных правил — подключён

`variant-tree.mjs` использует тот же `public/structure-rules.js`, что сервер и редактор правил. Повторный разбор грамматики собственными регулярными выражениями удалён. Для дерева используются:
- `StructureRules.parse()` — разбор правил;
- `StructureRules.templateFor()` — получение шаблона кода;
- общий набор правил по языку из `dict.structure`.

Тесты проверяют все 14 типов правил, шаблоны, обратные связи и то, что команда `удалить` не становится отношением дерева.

## 2. Типы отношений в дереве — разделены

Отношения не сводятся к общей группе «варианты продолжения» или «условия применения». Дерево показывает отдельные группы:

| Тип правила | Группа в дереве |
|---|---|
| `после` | Следует после |
| `внутри` | Расположение внутри |
| `не внутри` | Запрещённое расположение |
| `содержит` | Состав конструкции |
| `не содержит` | Запрещённое содержимое |
| `первым в` | Порядок элементов |
| `требует` | Зависимости |
| `обязательно` | Обязательные части |
| `можно` | Допустимые части |
| `значения` | Допустимые значения |
| `связывает` | Связи с другими языками |
| `читает` | Читаемые данные |
| `заметка` | Пояснения |
| `пишется` | Шаблон кода в корневом элементе |

Семейство имён CSS (например, `margin → margin-inline → margin-inline-start`) остаётся отдельной навигацией по именам. Оно не выдаётся за синтаксическое отношение.

## 3. Поиск: разделены контексты, объединены источники

В системе остаются разные входы, потому что у них разные задачи:

- `/api/variants` — короткое дополнение по токену/позиции курсора;
- `/api/search` — полнотекстовый поиск по библиотеке;
- `/api/search/shadow` — экспериментальный индекс для диагностики направленных фраз;
- `/api/search/task` — единый поиск по полному описанию задачи.

Новый task endpoint объединяет три источника:
1. направленные фразы из обычного словаря;
2. полнотекстовый поиск по фрагментам библиотеки;
3. дерево конструкций со структурными отношениями.

Результаты объединяются reciprocal-rank fusion: сравниваются позиции в независимых выдачах, а не несопоставимые исходные score. В ответе сохраняются источники совпадения, найденные целевые конструкции, языковые разделы и объяснения.

Экспериментальные фразы отдельного хранилища не включаются в обычный task search. Основной поиск использует канонический словарь и обычную языковую классификацию.

Для явно интерфейсных задач приоритет получают HTML, CSS, JavaScript и SVG. Python не отсекается, если в запросе явно указана серверная/Python-часть.

## 4. Сопоставление естественного языка

`query-phrase-match.mjs` — общий сопоставитель для дерева вариантов и направленного поиска. Он использует нормализацию, токены и русскую стемматизацию, различает точное, префиксное и частичное совпадение, сохраняет отрицание и проверяет контекст.

Есть защитные проверки для противопоставлений:
- массив/список и раскрываемый UI-блок;
- ссылка и кнопка;
- наведение и нажатие;
- внутренний и внешний отступ;
- толщина и размер шрифта;
- межбуквенный и межстрочный интервал;
- сохранение места и удаление элемента из потока;
- UI-задача и нерелевантные Python/SQL/file-I/O конструкции.

Эти проверки не заменяют языковые правила и не добавляют новые категории. Они ограничивают ложные совпадения поисковой гипотезы.

## 5. Поле задачи и автодополнение

- `vtree.js`: полное описание задачи отправляется в `/api/search/task`; запрос не ограничен четырьмя словами.
- `insert.js`: короткое контекстное дополнение у курсора остаётся отдельным режимом. Его короткий контекст намеренный: это автодополнение текущего токена, а не поле описания всей задачи.
- Оба режима используют общие конструкции и правила, но не смешивают задачу поиска и замену токена.
- В `insert.js` и `vtree.js` текстовые отношения выводятся как текст, а не как фрагмент кода с синтаксической подсветкой.
- Для устаревших запросов сохранены отмена fetch и проверка последовательности запросов.
