# Сверка совпадающих фрагментов, паспортов, заметок и ссылок

Дата проверки: 2026-11-06. Ветка: `audit/fixes-2026-11-06`.

Проверка read-only: файлы библиотеки не менялись и не удалялись. Отчёт сформирован скриптом `tools/code-lab/scripts/audit-library.mjs`, результаты CI приложены как artifact `code-lab-library-audit-ubuntu-latest`.

## Объём и целостность

- 2 385 файлов кода и 2 385 паспортов.
- Нет отсутствующих паспортов, невалидных JSON-паспортов, отсутствующих ID или повторяющихся ID.
- Нет несовпадений языка паспорта с расширением файла.
- 63 паспорта имеют пустое описание.
- Найдено 151 группа точного совпадения кода (302 файла). Это не 151 доказанный мусорный дубль.

## Сверка 151 группы точного совпадения кода

Для каждой пары сопоставлены:
- описание, заголовок, группа, теги, aliases, статус и component;
- полный набор wordNotes с координатами, текстом, типом, пояснением и источником;
- orphanNotes;
- URL в исходном коде и URL, встречающиеся в JSON-паспорте.

Результат:
- Во всех 151 парах паспорта отличаются по описанию, тегам, aliases и component.
- Ни в одной паре наборы wordNotes не совпадают полностью и нет ни одной полностью совпадающей заметки по координатам, токену, типу, тексту пояснения и источнику. Средний точный Jaccard для заметок равен 0.
- В 146 из 151 пар в одной версии заметок больше; типичная картина — 1 заметка в старом/облегчённом паспорте и несколько заметок в расширенном.
- В 28 группах у одной из копий присутствуют orphanNotes.
- URL-наборы совпадают внутри всех 151 пар. Только 11 групп содержат URL в исходном коде или паспорте; в остальных ссылок нет.
- Следовательно, удалять одну копию или просто выбирать паспорт с более длинным описанием нельзя: это потеряет заметки и метаданные. Нужна операция объединения с сохранением обеих сторон, после чего отдельная проверка конфликтующих заметок.

## Заметки

В библиотеке:
- 13 310 обычных wordNotes;
- 481 заметка типа `concept` — это пояснения понятий/конструкций, не подписи токенов;
- 70 orphanNotes; все 70 уже присутствуют среди wordNotes в том же паспорте. Это точные повторные записи внутри паспорта, но перед очисткой нужно проверить, не использует ли UI этот массив отдельно.

Позиционная сверка обычных заметок:
- 12 771 заметка совпадает с токеном в сохранённой позиции;
- 29 встречаются в коде ровно один раз, но в другой позиции;
- 90 встречаются в коде несколько раз, позиция не позволяет однозначно определить нужное вхождение;
- 1 составная заметка найдена как подстрока;
- 8 заметок не найдены в текущем коде.

В 293 заметках поля `kind` и `note` выглядят переставленными: в `note` хранится короткий тип токена, а в `kind` — текст пояснения. Само пояснение не потеряно. Это старый/альтернативный формат записи, а не повод автоматически менять значения без проверки читателя и редактора.

Восемь ненайденных заметок:
- `python/math-ssa.py`: две заметки для `N`;
- `python/var-по-истории-mvh8gqxd.py`: четыре заметки для `returns`;
- `python/асинхронное-ожидание-нескольких-сокетов-mvkjwp8b.py`: две заметки для `for`.

Их нельзя удалять автоматически: вероятно, часть относится к прежним версиям фрагментов или к неверным координатам/токенам. Нужна ручная сверка этих трёх исходников и паспортов.

## Внешние ссылки

В метаданных нет отдельного заполненного поля `externalLinks`, `links` или `references`. Ссылки в основном зашиты непосредственно в код и иногда повторяются в сериализованном тексте паспорта.

Найдено:
- 78 файлов кода с URL;
- 51 паспорт, в сериализованном содержимом которого встречаются URL;
- 67 уникальных URL после нормализации;
- среди адресов есть реальные справочные источники (например, MDN, ISS MOEX, Google Fonts, jsDelivr), тестовые `example.com`, локальные `localhost` и адреса-заглушки с шаблонными переменными.

URL внутри каждой пары точных дубликатов совпадают. Это не означает, что все URL являются внешними источниками: многие — демонстрационные адреса запросов, локальные адреса или тестовые endpoint. При объединении фрагментов их нужно сохранять как часть кода; отдельно от ссылок на документацию их следует помечать по назначению.

## Решение по очистке

1. Не удалять ни одну из 302 копий автоматически.
2. Считать эти 151 пары кандидатами на объединение, а не на удаление.
3. Для каждой пары выбрать один канонический файл, перенести в него более полное описание, теги, aliases, component и заметки обеих версий.
4. При совпадении координат и токена с разными пояснениями создавать конфликт на ручную проверку; не перезаписывать одну заметку другой.
5. Переносить URL в отдельные ссылки-источники только если они действительно ведут на документацию/источник, а не являются примером запроса.
6. Сохранять старые ID и пути как алиасы/redirect mapping до проверки всех ссылок и поисковых индексов.
7. Отдельно изучить 8 потерявших позицию заметок и 70 повторов в orphanNotes.
