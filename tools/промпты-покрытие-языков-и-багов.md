# Промпты: покрыть язык и баги через ИИ

Готовые запросы, чтобы любая модель (GPT, Claude, Mistral, GigaChat…) выдавала
результат **сразу в том формате, который понимают окна импорта** в Лаборатории.
Копируешь промпт → подставляешь `<ЯЗЫК>`/`<ТЕМА>` → ответ вставляешь в нужное окно.

---

## Куда вставлять результат

| Что получаешь | Куда | Формат строки |
|---|---|---|
| Пояснения к синтаксису | Опись → **📖 словарь пояснений** (указать язык) | `слово: пояснение` |
| Синонимы (смысл → термин) | Опись → **🔤 синонимы** | `термин: синоним, фраза` |
| Ошибки → что делать | Опись → **📖 словарь** (тот же язык) | `текст/симптом ошибки: причина и что сделать` |

Проверка после заливки: **📚 весь словарь** → чипы языков, кнопка **🔍 дубли**,
кнопка **🧹 обрывки кода**.

---

## Правила формата (иначе не распарсится / замусорится)

- Одна строка = одна запись. Без нумерации, без markdown, без «```».
- Разделитель — одиночное двоеточие `:` (не `::`), либо `|`, таб, « — ».
- **Ключ — это сам синтаксис** (токен/конструкция), пояснение — по-русски, своими
  словами, 1 фразой, **без кода внутри пояснения**.
- Ключи с пробелом/кириллицей не идут в автодополнение (это нормально — такие
  «понятия» находятся по смыслу через синонимы).
- Не вставлять в словарь **куски кода целиком** — чистка «обрывков кода» их удалит.
- Регистр ключа неважен (на сервере приводится к нижнему), дубли склеиваются.

---

## План: покрыть язык этапами (качественно, не за один присест)

1. Ключевые слова и операторы.
2. Встроенные типы и структуры данных.
3. Стандартная библиотека — по темам (строки, коллекции, файлы, время, сеть…).
4. Частые конструкции и идиомы (многословные ключи: `try/except`, `with open`, …).
5. Частые ошибки и как их чинить.
6. Синонимы — как новичок описал бы задачу словами.

Делай по одной теме за запрос — качество выше, дублей меньше.

---

## Промпты (копировать)

### 1. Синтаксис — словарь по теме
```
Ты точный справочник по языку <ЯЗЫК>. Тема: <ТЕМА, напр. "ключевые слова" / "методы строк" / "работа со списками">.
Дай список записей СТРОГО в формате, по одной на строку:
токен: краткое пояснение по-русски, 1 фраза, своими словами, без кода внутри пояснения.
Требования: 60–120 записей; ключ — реальный токен/метод/функция языка (например len, append, for, std::cout);
без нумерации, без markdown, без ```; не повторяйся. Если метод объекта — пиши как принято в языке.
```

### 2. Конструкции и идиомы (многословные ключи)
```
Для языка <ЯЗЫК> дай устойчивые конструкции/идиомы (многословные), формат по одной на строку:
конструкция: что делает и когда применяют, 1 фраза по-русски.
Примеры ключей: try/except, with open(...) as f, list comprehension, async/await, for...of.
Без кода в пояснении, без нумерации, без markdown.
```

### 3. Частые ошибки → что делать (для «🩺 решить»)
```
Для языка <ЯЗЫК> дай частые ошибки новичка и как их чинить. Формат по одной на строку:
краткий симптом или текст ошибки: вероятная причина и что сделать (1–2 фразы, по-русски).
Пример: "IndentationError: сбились отступы — выровняй вложенность пробелами, не мешай табы и пробелы".
40–80 записей, без нумерации, без markdown. Эти строки лягут в словарь и будут находиться по описанию проблемы.
```

### 4. Синонимы (смысл → термин)
```
Вот список терминов языка <ЯЗЫК>: <СПИСОК через запятую или по строкам>.
Для каждого дай русские синонимы и формулировки, как новичок описал бы задачу словами.
Формат по одной на строку: термин: синоним, другая формулировка, ещё фраза.
Пример: sort: сортировка, упорядочить, расставить по порядку. Без нумерации, без markdown.
```

### 5. «Только новое» — против дублей
Сначала скопируй текущий раздел кнопкой **⧉** в «📚 весь словарь», затем:
```
Вот уже имеющиеся записи (не повторяй их):
<ВСТАВИТЬ СКОПИРОВАННОЕ>
Теперь дай ТОЛЬКО НОВЫЕ записи по теме <ТЕМА> для языка <ЯЗЫК>, в том же формате
"ключ: пояснение", которых в списке выше нет.
```

---

## Несколько моделей сразу

- Один и тот же промпт отдай 2–3 моделям — получишь разный охват.
- Все ответы складывай в одно поле «разобрать» (можно подряд): дубли склеятся
  при вставке и на сервере.
- Если модель добавила нумерацию/markdown — попроси «переделай строго построчно
  `ключ: пояснение`, без markdown».

## Проверка качества покрытия

- «🩺 собрать непонятные слова» (в окне словаря): вставь реальный код на языке —
  соберёт слова, которых ещё нет в словаре, и даст готовый запрос для ИИ.
- После каждой заливки — **🔍 дубли** и **🧹 обрывки кода** в «весь словарь».

# Функциональное покрытие: рабочие куски и шаблоны

Словарь = *что значит* (терминология). Функциональное покрытие = *как сделать* —
рабочие **куски кода** и **большие шаблоны**. Это тоже генерится ИИ пачками и
грузится одним файлом.

## Формат импорта (JSON-массив кусков)
```json
[
  {"title":"Прочитать файл построчно","lang":"python","group":"Файлы",
   "desc":"когда брать, на что смотреть","code":"with open(path) as f:\n    for line in f:\n        process(line)"},
  {"title":"GET-запрос и JSON","lang":"python","group":"Сеть",
   "desc":"простой запрос с обработкой ошибки","code":"import requests\nr = requests.get(url, timeout=10)\nr.raise_for_status()\ndata = r.json()"}
]
```
Поля: `title` (по-русски, что делает), `lang`, `group` (раздел/категория), `desc`
(зачем/когда), `code` (настоящий код с `\n`). Дубли по коду склеиваются.

## Куда грузить
Меню → **«Куски кода»** → раскрыть **«📥 загрузить куски кода (пачкой)»** → вставить
JSON (или перетащить .json-файл). Потом — Библиотека/Опись, фильтр по языку.

## Промпты

### 1. Набор функциональных кусков по теме
```
Ты опытный <ЯЗЫК>-разработчик. Тема: <ТЕМА: строки / коллекции / файлы / HTTP / даты / ошибки / классы / асинхронность / парсинг…>.
Дай 15–30 РАБОЧИХ фрагментов «как сделать типовую задачу», каждый — минимальный самодостаточный пример.
Ответ — СТРОГО JSON-массив, без markdown и текста вокруг:
[{"title":"краткое что делает, по-русски","lang":"<ЯЗЫК>","group":"<ТЕМА>","desc":"когда брать, на что смотреть","code":"настоящий код с \\n, без заглушек ..."}]
```

### 2. Покрыть язык по категориям задач (по очереди)
```
Перечисли типовые КАТЕГОРИИ задач на <ЯЗЫК> (ввод-вывод, строки, коллекции, файлы, даты, сеть, ошибки, классы, асинхронность, парсинг, тесты…).
Затем по ОДНОЙ категории за ответ дай 2–4 рабочих куска в JSON-формате [{title,lang,group,code,desc}], group = категория. Так ничего не обрежется, а покрытие наберётся по категориям.
```

### 3. Большой шаблон (из кусков → на холст)
```
Распиши «<ЧТО СТРОИМ: напр. сайт с авторизацией, личным кабинетом и парсингом>» на <ЯЗЫК/стек> как последовательность осмысленных блоков.
Для каждого блока дай рабочий кусок в JSON [{title,lang,group,code,desc}], group = название блока; порядок = как собирать.
```
Загрузишь куски → собери из них «рецепт» (раздел Рецепты) → в конструкторе «＋ добавить → 📋 большой шаблон…» развернёт его на холст связанными блоками.

## Как мерить функциональное покрытие
Думай КАТЕГОРИЯМИ задач: есть ли кусок на каждую типовую? Промпт №2 гоняешь по
категориям по очереди — дыры закрываются системно, а не хаотично.

---

## Задачи (деревья решений)

Готовый промпт собирается кнопкой **Задачи → ⧉ промпт для ИИ**: в нём формат, правила, список уже имеющихся задач и (по выбору) названия кусков нужного раздела, чтобы ИИ ссылался на них, а не писал код заново. Ответ вставляется в **Задачи → 📥 пачкой** → «проверить» → «сохранить». Ссылки, которые не нашлись, видны в проверке; их можно поправить потом в «✎ править» (поиск над полем вставляет ссылку на кусок).
