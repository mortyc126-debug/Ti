## 1. Общая схема

Приложение: локальный веб-сервер на Node.js (только стандартная библиотека, **нет `package.json` и зависимостей**) и набор статических страниц. Всё хранится в обычных файлах.

```
Браузер  (public/*.html + *.js + style.css, меню: shell.js, темы и вкладки в «Настройках»: theme.js)
   │  fetch('/api/…')   JSON, ответы без кэша (Cache-Control: no-store)
   ▼
code-lab-server.mjs     Node http, слушает только 127.0.0.1:8788
   ├─ lib/library-store.mjs ─► library/<язык>/<id>.<ext> + .meta.json   (код и описания)
   ├─ lib/search.mjs ────────► индекс в памяти, строится из хранилища
   ├─ lib/describe-queue.mjs, ai-assist.mjs, ai-generate.mjs ─► api.mistral.ai  (ИИ, нужен ключ)
   ├─ lib/workspace.mjs ─────► папка проекта на диске (по выбору пользователя)
   ├─ lib/vendor.mjs ────────► code-lab/vendor/codemirror/<версия>/ ◄─ registry.npmjs.org (только по кнопке)
   ├─ flows/  recipes/  data/ ► JSON-файлы (схемы конструктора, рецепты, наборы данных)
   ├─ git (через execFile) ──► GitHub, по кнопке «синхронизировать»
   └─ интерпретаторы (node, python3, …) ─► запуск кода на машине пользователя (/api/run)
```

Принципы, на которых всё держится:
1. **Код — источник правды.** Подсветка и пояснения слов строятся из текста при каждой загрузке. Файл можно править в любом редакторе, сервер подхватит изменение.
2. **Описание живёт рядом с кодом**, в соседнем файле `*.meta.json`.
3. **Автор поля помечается** (`source.*`: `manual` / `imported` / `ai`), чтобы ИИ не затирал написанное человеком.
4. **ИИ только предлагает**, сохраняет человек, кроме очереди «описать всё», которая пишет в пустые поля.
5. **Всё локально.** Сервер слушает только свой компьютер; наружу ходит только по запросу пользователя (Mistral, npm, GitHub).

## 3. Где лежит библиотека и как устроена запись

Сервер использует `tools/code-lab/library/` (создаётся при запуске, поэтому в архиве исходников его может не быть). Для каждого куска два файла:

```
library/
├── css/
│   ├── example.css                 код (обычный текст)
│   └── example.css.meta.json       метаданные
├── js/ …  python/ …  sql/ …  html/ …  svg/ …  json/ …
├── _synonyms.json                  синонимы поиска (правятся руками, подхватываются без перезапуска)
└── _migration-report.json          отчёт переноса из templates/
```

Положили файл кода в `library/` руками, без `.meta.json`: кусок появится в списке со статусом `needs_description`, метафайл создастся при первом сохранении.

### Поля метафайла

| Поле | Содержание |
|---|---|
| `schema`, `id`, `file` | версия формата, идентификатор, имя файла кода |
| `title`, `lang`, `group` | название, язык, раздел (`Раздел / Подраздел`) |
| `desc`, `output` | что делает кусок; что получится на выходе |
| **`tags`**, `aliases` | **теги** и синонимы для поиска |
| `source` | автор полей: `{ title, desc, tags, aliases }`, значения `manual` / `imported` / `ai` |
| `status` | `described` или `needs_description` |
| `wordNotes` | пояснения к словам с позицией (`line`, `col`, `text`, `note`, `source: dict|custom`) |
| `orphanNotes` | пояснения, чьё слово исчезло из кода (возвращаются, когда слово появится) |
| `component` | данные для Конструктора: раздел, `provides`/`requires` (контракт), `collections`, `notes`, `lineNotes`, зависимости |
| `legacy` | пометка куска, перенесённого из `templates/` |
| `architectureNote` | заметка об архитектуре (у кусков CSS) |
| `generated` | `{ by: 'ai' }`: кусок создан ИИ (статусы `not_verified` / `not_run`) |
| `enriched` | пометка от дополнения тегов/описаний: ИИ уже прошёл по куску (поле добавлено доработкой, раздел 14) |

Объект, который отдаёт `store.get()`, совместим со старым форматом карточки (`id, lang, group, title, desc, lines, output, descAt, component`), поэтому интерфейс не менялся при переходе на файлы.

### Остальные хранилища

| Папка | Что хранится | Через что |
|---|---|---|
| `templates/` | старые карточки-шаблоны (454 JSON). При первом запуске переносятся в `library/`; потом не читаются и не меняются | `lib/migrate.mjs`, `migrate-templates.mjs` |

Старые карточки `templates/` — не то же самое, что `data/` (хранилище произвольных данных).

## 4. Сервер `code-lab-server.mjs`

**Запуск:** `node tools/code-lab-server.mjs [порт]`, по умолчанию порт 8788, адрес `http://localhost:8788/`. Заголовочный комментарий в самом файле устарел (описывает времена, когда шаблон был одним JSON).

**Порядок старта:** `store.init()` (сканирует библиотеку, при первом запуске переносит `templates/`) → `describeQueue.init()` (возвращает зависшие `running` в `queued`) → `search.init()` → `vendor.init()` → `listen(127.0.0.1)`.

**Первым делом обработчик проверяет адрес** для маршрутов `/api/*` и `/vendor/*`: `Host` должен быть `localhost` / `127.0.0.1` / `[::1]` с портом сервера, `Origin`, если есть, тоже должен быть своим. Иначе ответ 403. Это закрывает запросы с чужих сайтов и подмену адреса (DNS rebinding).

**Статика:** всё из `code-lab/public/`, без кэша. Если в странице ещё нет `id="lab-mistral-settings"`, сервер перед `</body>` вставляет: плавающую кнопку `#lab-mistral-open` («⚙ Настройки», правый нижний угол, `position:fixed`); окно `#lab-mistral-settings` (`.panel` с заголовком `#lab-mistral-title`, полем `#lab-mistral-key`, кнопками «Сохранить / Проверить подключение / Удалить ключ / Закрыть», ссылкой «Редактор кода…» на `/vendor.html`, строкой `#lab-mistral-status`); свой `<style>` и скрипт, который читает и пишет ключ в `localStorage['codeLab.mistralApiKey']`; и следом `<script src="/ai-settings.js">`. Стили окна заданы строкой внутри сервера (фиксированные цвета; `theme.js` перекрашивает их под тему). Файл `ai-settings.js` в прежних версиях описания не упоминался; его код я не видел.

### Маршруты

| Группа | Маршруты | Назначение |
|---|---|---|
| Библиотека | `GET /api/list`, `GET /api/template?id=` | список (только метаданные) и полный кусок |

## 7. Поиск

Ищет по названию, описанию, тегам, синонимам, разделу, результату, пояснениям слов, самому коду и контракту. Что умеет: словоформы (толщина / толщину), `font-weight` целиком и по частям, `querySelector` как `query` + `selector`, начало слова, одна опечатка, синонимы из `library/_synonyms.json` и `default-synonyms.json`.

Веса полей: название 6, теги 5, синонимы 5, раздел 3, описание 3, код 2, результат 1,5, пояснения 1,5, контракт 1. Результат сортируется по сумме баллов; слабые совпадения отсекаются по порогу от лучшего (в архиве 20 %).

Ответ: `{ hits:[{ id, score, why:[{ q, kind, via, found, in }] }], total, terms }`. Поле `why` объясняет, чем куски совпали (`kind`: название, тег, код и т. д.).

## 9. Редактор CodeMirror 5 (`vendor`)

Подсветка и редактирование кода через CodeMirror 5 (ветка 5.x, на дату в реестре последняя 5.65.21). Файлы лежат локально, интернет нужен только на момент скачивания.

```
code-lab/vendor/codemirror/
  manifest.json         active, previous, installed{версия: { published, integrity, test, … }}, lastCheck
  5.65.21/              lib/, mode/, addon/, theme/, keymap/, LICENSE, package.json, files.json (sha256 каждого файла)
```

**Жизненный цикл версии** (страница `vendor.html`, ссылка «Редактор кода…» в Настройках):
проверить обновления → скачать (в отдельную папку, **не включается**) → проверить на вашей библиотеке (скрытое окно прогоняет все куски и 16 режимов через разбор, шлёт результат серверу) → включить → при необходимости откатить или выключить.

**Правила безопасности:** только ветка 5.x и точные версии; загрузка только с `registry.npmjs.org` по https и без редиректов; архив сверяется с контрольной суммой из реестра; из архива берутся только `lib/mode/addon/theme/keymap`, опасные пути и ссылки отвергаются; перед включением файлы сверяются с `files.json` (подмена блокирует включение); версия младше 14 дней ставится только с подтверждением; включить без успешной проверки нельзя; изменяющие запросы требуют заголовок `X-Code-Lab: 1` и свой `Origin`.

**Клиентская сторона:** `cm-bridge.js` загружает активную версию и режимы по языку (карта `MODE_MAP` в `vendor.mjs`: js, ts, json, css, html, svg, sql, python, bash, powershell, go, ruby, php, lua, r, perl). `CMBridge.enhance(textarea, язык)` превращает поле в редактор, а `ta.value` продолжает читаться и записываться как раньше. Если редактор не установлен или не загрузился, поля остаются обычными.

**Где подключён:** формы «добавить» и «правка» на странице Библиотека (`app.js`). Остальные поля (песочница, конструктор, каталог) пока на прежнем вводе. Автодополнение (аддон `show-hint`) в пакете есть, но не подключено.

### Вкладки редактора (`tabs.js`, с 24.10.2026)

Надстройка над песочницей: вместо стопки панелей `.sb-ed` — полоса вкладок сверху и один видимый активный редактор. Не трогает ни `sandbox.js`, ни `workspace.js`, работает только через `window.codelabSandbox.getFiles()/setFiles()` и показ/скрытие панелей классом `.sb-active`. Оборачивает `#sbEds` в `.sb-edcol` с полосой `#sbTabs`; на `#sbEds` вешает класс `tabbed` (в CSS `constructor.html`: `.sb-eds.tabbed > .sb-ed{display:none}`, `.sb-active{display:flex}`). Активная вкладка запоминается в `localStorage['codelab_sb_active']`. Вкладка: точка «не сохранено» (из класса `.ws-dirty`, который ставит `workspace.js` на файлы проекта), имя файла, крестик закрытия. Перетаскивание меняет порядок (через `setFiles`). Два `MutationObserver` на `#sbEds`: по `childList` (открыли/закрыли/переставили файл) и по атрибуту `class` в поддереве (появление/снятие `.ws-dirty`) — пересобирают полосу. Закрытие последней вкладки создаёт пустой `файл.txt`. Наружу отдаёт `window.codelabTabs = { setActive, rebuild, active }` (нужен `fileio.js`, чтобы открытый файл сразу стал активной вкладкой).

### Открыть/сохранить файл с диска (`fileio.js`, с 24.10.2026)

Две кнопки в панели песочницы рядом с «+ файл»: «📂 открыть…» и «💾 на диск…». Это НЕ папка проекта (её ведёт `workspace.js`) — отдельные файлы откуда угодно с диска. В Chrome/Edge через File System Access API (`showOpenFilePicker`/`showSaveFilePicker`): открытие читает файл и кладёт новой вкладкой (язык по расширению), дескриптор помнится по `id` куска в `Map`, поэтому «на диск…» перезаписывает тот же файл без повторного выбора; если дескриптора нет — спрашивает, куда (как «сохранить как»). В браузерах без API откат: открытие через скрытый `<input type=file multiple>`, сохранение — скачиванием (`Blob` + `a[download]`). Дескрипторы живут только в памяти (после перезагрузки «на диск…» снова спросит место). Активный файл для сохранения берётся по `localStorage['codelab_sb_active']` (или первый). Сообщения выводит в строку `#wsMsg` из `workspace.js`, если она есть.

### Поиск в песочнице (`search.js`, с 24.10.2026)

Кнопка «🔎 поиск» в панели песочницы и Ctrl/Cmd+F открывают полосу поиска под вкладками (`.sb-find` в `.sb-edcol`). Два режима (сегмент-переключатель): «в файле» — ищет в активном файле; «по приёмам» — по всем открытым файлам, слово-приём разворачивается в набор регулярок через словарь `TRICKS` в модуле (цикл→for/while/forEach/.map/do, условие→if/else/switch/?:, функция→function/=>/def/func, массив, объект, класс, импорт, вывод→console.log/print/echo/alert, переменная, событие, ошибка→try/catch/throw, запрос→fetch/axios). По умолчанию регистр не учитывается, галочка «Аа» включает учёт. Совпадения считаются (`n / m`), подсвечиваются в CodeMirror через `markText` (`.cm-find`, текущее — `.cm-find-cur`); Enter/Shift+Enter и кнопки ‹ › листают, при совпадении в другом файле переходит на его вкладку (`window.codelabTabs.setActive`). «Начать с последнего»: по файлу помнится смещение последнего совпадения (`lastPos`), поиск стартует с него. Esc закрывает. Работает и без CodeMirror (обычная `textarea` — выделение через `setSelectionRange`, без подсветки всех совпадений). Использует только core-методы CM (`posFromIndex`, `markText`, `setSelection`, `scrollIntoView`), экземпляр берёт из `ta.__cm`.

### Форма заполнения для куска-кода (`rawInspFields`, расширено 24.10.2026)

Вкладка «Настроить» у raw-узла («свой код», в т. ч. кусок из каталога) теперь строит форму ввода по объявлениям `const/let/var`. Раньше `VAR_RE` требовал однострочное `имя = значение;` — многострочная константа (объект на несколько строк) под него не попадала, и показывалось только примечание. Теперь `rawDecls()` (гашение строк/комментариев `_rawBlank`, глубина скобок, `_rawValEnd`) находит одно- и многострочные объявления верхнего уровня; для объекта-значения `rawObjFields()` даёт поле ввода на каждый ключ («развилки»; стандартные имена из `RAW_STD_KEYS` приглушены, авторские ярче). Правка поля пишется обратно в код по имени переменной/ключа (`setDeclValue`/`setFieldValue`, перечитывают код каждый раз — смещения не устаревают), синхронит «весь код» (`syncRawCode`) и обновляет узел/превью. Это та же идея, что у `inspect.js` (разбор на компоненты), но в инспекторе конструктора.

### Разбор файла на компоненты (`inspect.js`, с 24.10.2026)

Кнопка «🧩 разобрать» в панели песочницы открывает панель `.sb-insp`, встроенную в раскладку песочницы между кодом и превью (flex-ребёнок, не overlay — не наезжает). Для активного JS/TS-файла разбирает код на компоненты: const/let/var, function, class. Объявления ищутся на самом мелком уровне, где они есть (`parse()` собирает все с глубиной и берёт минимальную) — поэтому находятся и константы внутри обёртки-IIFE `(() => { … })()`, а не только на глубине 0. Список с бейджем вида и строкой; при открытии авто-выбирается первый компонент (панель не пустая). Клик по компоненту (или по имени в коде) → «Подробно»: роль (своё имя / стандартное / не объявлено тут), для const/let — значение в редактируемом окошке с «💾 записать в код» (пишет обратно по смещению), для function/class — сигнатура + «→ перейти»; поля объекта-значения («развилки») с пометкой «станд.»/«своё» (`STD_KEYS`); **«Связи с компонентами файла»** — видами из единого словаря `window.CODE_RELATIONS` (`relations.js`), `classifyRel()` по телу компонента определяет вид (приоритет сверху вниз): `расширяет` (extends), `создаёт` (new), `слушает` (.addEventListener), `шлёт событие` (.dispatchEvent/.emit), `меняет` (.push/.set/… или `.поле =`), `вызывает` (`имя(`), `читает` (`.поле`), иначе `использует`. Чипы раскрашены `relationColor`; «Используется» — через `window.codelabNav.analyze`. Набор видов — тот же, что используется по всему проекту (рёбра конструктора, Опись, импорт связей из текста). Клик по ключевому слову `const`/`function`/… ведёт к объявлению на этой строке (а не трактуется как имя); для ключевых слов список вхождений не вываливается.

Блок «Связи этого куска в проекте» (`#inspProj`): при открытии файла `loadProjectRels()` шлёт `POST /api/relations/piece {code, title}`. Сервер ищет кусок в библиотеке по нормализованному коду (или названию), затем проходит все сохранённые схемы (`flows/`), собирает рёбра, где этот кусок участвует, и возвращает `[{dir:'out'|'in', rel, other, scheme}]` (виды — id из `CODE_RELATIONS`, дубли схлопнуты). В панели — чипы `relationColor` с направлением (`этот → other` / `other → этот`) и схемой в подсказке. Если код не совпал с сохранённым куском — блок скрыт. Так в одной панели и внутренняя структура файла, и его место в проекте — одним словарём связей. Разбор эвристический (`blank()` гасит строки/комментарии, глубина скобок, `valueEnd`/`bodyEnd`). Пока JS/TS. Единый словарь связей — тот же, что у рёбер конструктора и Описи; свои термины не плодим.

### Клик по слову: определение и использования (`navigate.js`, с 24.10.2026)

Галочка «🔗 связи по клику» в панели песочницы (рядом с «пояснения по клику»). Когда включена, клик по имени показывает попап `.nav-pop`: где имя **задано** (определение) и где **используется**, по всем открытым файлам. Эвристика по имени, не настоящий анализатор: определение — строка, где по слову совпали `function/def/func/fn/sub W`, `class W`, `const/let/var W`, `W = функция/стрелка/объект/массив`, `W(...) {` или присваивание `W =`; остальные вхождения (по границе `(?<![\w$])W(?![\w$])`) — использования. Ключевые слова и слова короче 2 символов пропускаются (`STOP`). Каждая ссылка кликабельна: переход на нужную вкладку (`window.codelabTabs.setActive`) и выделение места (CM `posFromIndex`+`setSelection`+`scrollIntoView`, либо `textarea.setSelectionRange`). Слово под курсором берётся через CM `coordsChar`+`findWordAt`+`getRange`, в обычной `textarea` — вокруг каретки. Наружу отдаёт `window.codelabNav = { analyze, jump }` (пригодится будущей панели связей).

## 11. Безопасность

Сервер умеет **выполнять код** (`/api/run`), **писать файлы в выбранную папку** (`/api/ws/*`) и **отправлять изменения на GitHub** (`/api/git/sync`). Поэтому доступ к нему должен быть только у вашей страницы.

| Мера | Где |
|---|---|
| сервер слушает только `127.0.0.1` | `listen(PORT, '127.0.0.1')` |
| проверка `Host` и `Origin` для `/api/*` и `/vendor/*` (403 на чужие) | начало обработчика; ставится `apply-cm5-patch.mjs` (отключается флагом `--no-guard`) |
| изменяющие запросы CodeMirror требуют `X-Code-Lab: 1` | `vendor`-маршруты |
| пути ограничены корнем (`within()`, проверка `..`, символических ссылок в workspace) | сервер, `workspace.mjs` |
| ключи не в файлах: Mistral только в окружении или `localStorage`; в файл очереди не пишется | `describe-queue.mjs` |

**Что осталось:** ответы API по-прежнему содержат `Access-Control-Allow-Origin: *`; защита держится на проверке адреса и источника запроса, а не на запрете CORS. Не открывайте сервер по IP в сети и не пробрасывайте порт: вся защита рассчитана на `localhost`.

## 13. Эксплуатация

- **Запуск:** `node tools/code-lab-server.mjs [порт]`. Ключ Mistral: `$env:MISTRAL_API_KEY = "…"` (PowerShell) или окно «Настройки».
- **Резервные копии:** все данные это обычные файлы. Достаточно `library/`, `flows/`, `recipes/`, `data/`. Лучше держать их в git.
- **GitHub:** `POST /api/git/sync` добавляет только `library/`, `flows/`, `recipes/` (непустые), делает коммит «Лаборатория: мои шаблоны и схемы», подтягивает серверные изменения (`pull --rebase --autostash`, при конфликте откат) и делает `push`.
- **Обновление файлов проекта:** патчеры `apply-*.mjs` (сначала `--check`), каждый кладёт копию `<файл>.bak-…`.
- **Обновление CodeMirror:** страница `vendor.html`, ничего не ставится само.
- **Миграция старых карточек:** автоматически при первом запуске; вручную `node tools/migrate-templates.mjs` (`--dry`, `--force`).
- **Обновление интерфейсных файлов:** положить `shell.js`, `theme.js`, `style.css`, `constructor.html` в `code-lab/public/` с заменой (вместе: `shell.js` подключает `theme.js`), закрыть вкладку лаборатории и открыть заново, Ctrl+F5. Перезапуск сервера не нужен: статика отдаётся с `no-store`.
- **Открывать только через сервер:** `http://localhost:8788/…`, не двойным кликом по файлу (иначе не загрузятся `style.css` и скрипты, останутся голые кнопки). Если вместо Лаборатории открывается чужая страница (например, «HTML и CSS конструктор» без бокового меню), на порту 8788 работает другой сервер: `Get-NetTCPConnection -LocalPort 8788 -State Listen`. При запуске нашего сервера он печатает «Лаборатория кода: http://localhost:8788/» и путь «Библиотека: …».
- **Диагностика в браузере:** F12 → Console. Ошибка 404 со ссылкой на `constructor.js` означает, что сервер не нашёл файл в `public/`; `ERR_CONNECTION_REFUSED` означает, что сервер не запущен.

## 15. Известные ограничения и особенности

1. **Все 520 кусков библиотеки «недоделанные» по порогам `isIncomplete`:** ни у одного нет синонимов (`aliases`), у 318 нет тегов. Первый запуск «описать всё» поставит в очередь всю библиотеку: при паузе 1,5 с это порядка получаса запросов. Пороги задаются в начале `describe-queue.mjs` (`MIN_DESC`, `MIN_TAGS`, `MIN_ALIASES`).
2. **Нестандартные метки автора.** У 66 кусков в `source` стоят метки вроде `catalog extension`, `added for catalog coverage`, `added for search-oriented coverage`. Хранилище знает только `manual` / `imported` / `ai`, поэтому такие поля **не защищены** от перезаписи ИИ. В исходной очереди это не проявлялось (она берёт только куски без описания), но при выборе «недоделанных» (раздел 14) эти куски попадают в очередь. Если это ваши правки, приведите метки к `manual` или `imported`.
3. **Поиск сервера подключён только в скрытом каталоге и в рецептах** (раздел 6). Правки выдачи и порога затрагивают именно их.
4. **`/api/dedup` необратим** без git: он удаляет куски с одинаковым кодом в одном языке, оставляя самый полный.
5. **Лимит описания:** `/api/edit` и `/api/ingest` обрезают описание до 400 символов, а очередь ИИ пишет до 1200.
6. **`data/description-jobs.json`** лежит в той же папке, что и наборы данных, и, судя по коду `/api/data/list`, отображается в списке «Данные» как один из наборов.
7. **Лишнее в проекте:** копия `DESCRIPTION-QUEUE.md` внутри `templates/`, архив `library/css.zip`.
8. **Два падающих теста** конструктора (раздел 12).
9. **`recipes/` пуста**, `vendor/` и `workspace.json` появятся только после первого использования.
10. **Окно «Настройки» с вкладками не подтверждено.** По проверке в консоли (24.10.2026) `window.codelabTheme` существует, окно `#lab-mistral-settings` и `.st-tabs` есть, то есть вкладки построены. Но заголовок оставался «ИИ: сервисы и ключи» (его, по-видимому, переписывает `ai-settings.js`), а старт окна на вкладке «Стиль» пользователь не подтвердил; после последней замены `theme.js` сообщила «всё по-старому». Причина не найдена: нужен код `public/ai-settings.js`.
11. **Фон-картинка и слои** написаны, но не проверены в браузере. Меняется только то, что идёт через переменные; на других страницах (Опись, Библиотека) могут остаться жёстко заданные цвета. Картинки хранятся в `localStorage` (общий лимит браузера около 5 МБ).
12. **Скорость перетаскивания границ:** правки в `style.css` сделаны, но не проверены. Не проверены и вероятные причины тормозов: `grow()` в `shell.js` (пункт «Что делает `shell.js`»), обработчики границ в `constructor.js` (строки около 1691–1738), вызовы `cm.refresh()`.
13. **Плавающая кнопка «⚙ Настройки»** закрывает низ правой панели; её вставляет сервер, она не перенесена.
14. **План интерфейса (не сделано):** масштаб в угол холста; сворачиваемые превью и боковые панели; убрать дубли кнопок («скачать» и «в каталог» справа в инспекторе); общие размеры кнопок (`--btn-h`) в `style.css`; плавающая панель ИИ по выделению кода (CodeMirror `cursorActivity` и `ai-assist.mjs`); перенос кнопки «Настройки».
