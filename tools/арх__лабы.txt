# Лаборатория кода — архитектура

Состояние на 29.10.2026. Документ описывает то, что есть сейчас; история правок — в `git log`.

## 1. Что это и на чём держится

Локальный менеджер кусков кода: сервер на Node.js (только стандартная библиотека, нет `package.json` и зависимостей) и набор обычных HTML/JS-страниц без сборщика. Все данные — обычные файлы.

Принципы:
1. **Код — источник правды.** Подсветка, пояснения, подписи, связи строятся из текста при загрузке. Файл можно править в любом редакторе.
2. **Описание живёт рядом с кодом** — в соседнем `*.meta.json`.
3. **Автор поля помечается** (`manual` / `imported` / `ai`), ИИ не затирает написанное человеком.
4. **ИИ только предлагает**, сохраняет человек. Исключение — очередь «описать всё», она пишет лишь в пустые поля.
5. **Ничего не размечается поштучно.** Подписи, связи, деревья вариантов, проверки выводятся из словаря, синонимов, правил языка и кода; человек правит только исключения — формами в Описи или ответом ИИ на готовый промпт.
6. **Всё локально.** Сервер слушает только свой компьютер; наружу ходит только по запросу (провайдер ИИ, npm за CodeMirror, GitHub).
7. **Без эмодзи** — нигде: ни в интерфейсе, ни в коде, ни в коммитах.

```
Браузер  public/*.html + *.js (меню shell.js, словарь kwdict.js, языки langs.js)
   │  fetch('/api/…')  JSON, Cache-Control: no-store
   ▼
code-lab-server.mjs   http, только 127.0.0.1:8788
   ├─ lib/library-store.mjs ─► library/<язык>/<файл> + .meta.json
   ├─ lib/search.mjs ────────► индекс в памяти
   ├─ lib/variant-tree.mjs, code-names.mjs, contract-labels.mjs ─► подсказки и разбор кода
   ├─ public/code-links.js, structure-rules.js ─► общие со страницей (через require)
   ├─ словари ───────────────► public/keyword-dict.json + public/dict/
   ├─ lib/ai-* ──────────────► провайдер ИИ (Mistral / GigaChat / OpenAI-совместимый)
   ├─ lib/workspace.mjs ─────► папка проекта на диске
   ├─ lib/vendor.mjs ────────► vendor/codemirror/<версия>/ ◄─ registry.npmjs.org (по кнопке)
   ├─ git (execFile) ────────► GitHub, по кнопке
   └─ интерпретаторы ────────► /api/run (node, python3, …)
```

## 3. Хранилище

### Куски — `library/`

Раскладка по языкам, на кусок два файла: `example.css` (код) и `example.css.meta.json` (описание). Служебные: `_sections.json` (дерево разделов), `_synonyms.json` (синонимы поиска, правятся руками, подхватываются без перезапуска), `_migration-report.json`. Файл кода без метафайла появляется в списке в разделе «Не разобрано» со статусом `needs_description`; метафайл создаётся при первом сохранении. Сейчас ≈2350 кусков.

| Поле метафайла | Что в нём |
|---|---|
| `schema`, `id`, `file` | версия формата, идентификатор, имя файла кода |
| `title`, `lang`, `group` | название, язык, раздел `Раздел / Подраздел` |
| `desc`, `output` | что делает; что получится |
| `tags`, `aliases` | теги и синонимы для поиска |
| `source` | автор каждого поля: `manual` / `imported` / `ai` |
| `status` | `described` / `needs_description` |
| `wordNotes`, `orphanNotes` | пояснения к словам с позицией; «осиротевшие» возвращаются, когда слово появится |
| `labels` | свои подписи к именам «даёт / нужно» (главнее автоматических) |
| `component` | для Конструктора: `provides`/`requires`, `collections`, заметки, зависимости |
| `legacy`, `generated`, `enriched`, `architectureNote` | перенесён из `templates/`; создан ИИ; ИИ уже дополнил; заметка |

`store.get()` отдаёт объект старого формата карточки (`id, lang, group, title, desc, lines, output, descAt, component`) — интерфейс не менялся при переходе на файлы. Ранги авторства (`applyDescription`): `ai`=1 < `imported`=2 < `manual`=3; теги и синонимы ИИ только дополняет; короткое описание (до 60 знаков) может переписать.

### Разделы — `library/_sections.json`

`tree` — 14 разделов с подразделами (последний «Не разобрано»), `rules` — перенос старых разделов «старый путь => новый путь» (самое длинное совпадение начала; `/ *` — оставить прежний подраздел). Модуль `lib/sections.mjs`. «Разложить неразобранное» (`suggestSections`): до 3 разделов по 7 самым похожим разложенным кускам (слова названия ×3, тегов и синонимов ×2, описания и кода ×1, вес по редкости); одноимённый кусок первым, полный дубль кода — пометка «удалить». Применяется только отмеченное. Окно — Опись → «дерево разделов» (`sections-ui.js`).

### Словари — `public/`

| Файл | Что | Правится |
|---|---|---|
| `keyword-dict.json` | общие слова (`words`) и разделы HTML/CSS базы | Опись → «словарь пояснений» без языка |
| `dict/langs/<язык>.json` | слова и конструкции языка с пояснениями (js ≈2200, python ≈3700, css ≈650, html ≈650) | «словарь пояснений» с языком |
| `dict/synonyms.json` | термин → фразы-смыслы («margin» ← «внешний отступ»), ≈1700 терминов | «синонимы» |
| `dict/examples.json` | термин → кусок-пример | «весь словарь» → «пример» |
| `dict/relations.json` | правки связей слов `{язык|*: {слово: связь}}` | «связи слов» (раздел 13) |
| `dict/structure.json` | правила структуры `{язык: [строки]}` | «правила структуры» (раздел 12) |

Сервер собирает всё в `kwDict()` (кэш в памяти) и отдаёт `GET /keyword-dict.json` (`?lang=X` — только этот язык плюс общее). На странице — общий кэш `window.codelabKwDict(lang?)` (`kwdict.js`), сброс `codelabKwDictReset()`. Формы Описи сбрасывают кэш сервера сами; правки файлов словаря мимо форм (в т. ч. `git pull`) требуют перезапуска сервера. Регистр: новые записи хранят ключ как написан; у старых (строчных) регистр для показа восстанавливается по коду библиотеки (`caseMapFrom`: queryselector → querySelector). Ввод «слово: пояснение» режется по последнему разделителю перед первым русским словом (`body { margin: 0 }: …` не обрывается); CSS «свойство: значение: пояснение» поддерживается. Алиасы языков (`canonLang`): javascript→js, py→python, c++→cpp и т. п.

## 4. Сервер `code-lab-server.mjs`

**Запуск:** `node tools/code-lab-server.mjs [порт]`, по умолчанию 8788 → `http://localhost:8788/`. Печатает «Лаборатория кода: …» и путь библиотеки. Заголовочный комментарий в файле устарел (говорит про `templates/`).

**Порядок старта:** `store.init()` (сканирование, миграция `templates/`) → очередь описаний (зависшие `running` → `queued`) → поиск → `vendor.init()` → папки `library/ flows/ data/ recipes/ tasks/` → `listen(127.0.0.1)` → прогрев подписей для `/api/list?labels=1`.

**Статика:** `code-lab/public/`, без кэша. В страницу без `id="lab-mistral-settings"` сервер перед `</body>` вставляет плавающую кнопку «Настройки» и окно ключей ИИ, затем `ai-settings.js` (провайдеры); `theme.js` добавляет в окно вкладку оформления.

**Маршруты:**

| Группа | Маршруты |
|---|---|
| Куски | `GET /api/list` (`?labels=1` — с подписями), `/api/template?id=` (+ `labels`, `contract`), `POST /api/add` (дубль по коду обновляется), `/api/edit`, `/api/delete`, `/api/dedup` (необратимо без git), `/api/ingest`, `/api/import`, `/api/import-collection`, `/api/library/restore`, `/api/similar`, `/api/piece/terms`, `/api/annotate`, `/api/annotate-all` |
| Разделы | `GET /api/sections`, `POST /api/sections/plan|save|apply|suggest|assign` |
| Поиск | `GET /api/search?q=&lang=&limit=` |
| Подсказки и разбор | `GET /api/variants?q=&lang=`, `POST /api/code/names {code, lang}`, `POST /api/contract/labels {text, dry}` |
| Словари | `POST /api/dict/add|synonyms|example|remove|clean`, `/api/dict/unknown`, `/api/dict/audit`, `/api/dict/gaps`, `/api/dict/usage`, `/api/dict/pieces`, `GET|POST /api/dict/relations`, `GET|POST /api/dict/structure`, `GET /keyword-dict.json` |
| ИИ | `POST /api/describe`, `GET /api/jobs`, `POST /api/ai-complete|ai-apply|ai-ask|ai-gaps|ai-generate|ai-create`, `GET /api/ai-langs`, `/api/ai/models`, `/api/ai/config` |

| Схемы, рецепты, данные | `/api/flows/*`, `/api/recipes/*`, `/api/data/*`, `/api/relations/piece` |

## 6. Клиент

### Меню и страницы

`shell.js` строит боковое меню: **Главная**, **С чего начать** · **Опись**, **Библиотека** · **Конструктор** · **Куски кода** (`schema-json.html`, загрузка данных). Внизу — «названия: сначала по-русски» и индикатор сервера. Поиск в меню — по всей программе: разделы, куски (`/api/search`), словарь с синонимами, рецепты. Меню сворачивается и меняет ширину перетаскиванием (двойной клик — 230 px). Глобально: модальное окно не закрывается одиночным кликом мимо — только двойным или кнопкой.

Вне меню, по адресу: `tasks.html`, `recipes.html`, `catalog.html` (старый каталог), `component.html` (страница одного куска), `vendor.html`, `vendor-test.html`.

### Опись (`inventory.html` / `inventory.js`)

Таблица кусков (первые 300 строк, «показать ещё»; фильтры — по всем), колонки «даёт / нужно» с подписями (`contract.js`). На виду: **словарь пояснений**, **весь словарь**, **синонимы**, **правила структуры**, **связи слов**, **дерево разделов**. В «⋯ ещё»: разделы из текста, подписи (`labels-ui.js`), связи из текста, скопировать список, убрать дубли. Панель ИИ — `ai-tools.js`.

### Конструктор (`constructor.html` / `constructor.js`)

Три колонки: палитра, центр (холст или песочница), инспектор.

- **Палитра:** поиск, фильтр языков, «Базовые блоки» и дерево разделов каталога. Название куска целиком, с переносом; «удалить» появляется поверх строки при наведении. У одинаковых названий в одном разделе под названием — первая фраза описания или первая строка кода. «авто-разложить» — раздел по смыслу там, где пуст. **Клик:** в режиме холста — блок на холст; в режиме песочницы — код в открытый файл у курсора (`insertToSandbox`): с новой строки, с тем же отступом, курсор в конец вставленного; кусок другого языка — в открытый файл этого языка, вкладка переключается.
- **Холст:** граф блоков, авто-связи по контрактам, сборка и запуск.
- **Инспектор:** вкладки «Код» и «Пояснение». Новый блок открывается на «Коде»; на «Пояснении» сверху тоже код блока. «Чем соединить» — куски-кандидаты по контрактам.
- **Песочница** (кнопка «песочница» / «к визуалу», `codelab_mode`): вкладки файлов, CodeMirror 5, живой предпросмотр, консоль. Панель (`sb-toolbar.js`): «запустить · Файл ▾ · Вид ▾ · Подсказки ▾»; поиск по файлу (Ctrl+F) — в «Вид», «спросить ИИ» и галочка «подсказки при наборе» — в «Подсказки».

## 7. Поиск (`lib/search.mjs`)

Документ — кусок из 9 полей с весами: название 6, теги 5, синонимы-алиасы 5, раздел 3, описание 3, код 2, результат 1,5, пояснения слов 1,5, контракт 1. Ключи: «ё»→«е», основа слова (Snowball), составные (`font-weight`) целиком и по частям, camelCase по частям; около 150 стоп-слов.

Варианты слова запроса: точное 1; части составного 0,8; синоним 0,85; начало слова 0,5; обрезанная основа 0,45; опечатка 0,4 (только если больше ничего, от 5 букв, та же первая буква, одна правка).

**Базовый балл** — BM25 (K₁=1,2, B=0,4): лучший вариант по слову плюс до 35 % остальных (потолок 1,5 от лучшего), × (доля найденных слов)², запрос целиком в названии ×1,6. Отсев — всё, что меньше 35 % лучшего базового балла.

**Понятность** меняет только порядок: итог = √(базовый) × понятность. Слова запроса в названии — до ×2,5 (точное слово весит больше начала и синонима); короткое название ×1,2 … длинное ×0,7; короткий код ×1,15 … длинный ×0,8; язык открытого файла ×1,3, чужой ×0,75; кусок-пример словаря или из задачи ×1,2.

Ответ: `{hits:[{id, score, why:[{q, kind, via, found, in}]}], total, terms}`. Индекс пересобирается при изменении хранилища или `_synonyms.json`.

## 8. Подсказки и разбор: общая идея

Слова кода соединяются со смыслом через словарь и синонимы; связи, правила и подписи выводятся автоматически; исключения правятся формами Описи; для массового пополнения у каждой формы есть «промпт для ИИ» — ответ вставляется в ту же форму. Сервер и страница разбирают правила одним кодом (`public/*.js` через `require`).

## 9. Подсказки при наборе (`insert.js` + `lib/variant-tree.mjs`)

Одно окошко у курсора. Открывается при наборе (по `keyup` и по `input` — ввод через раскладку или IME может прийти без `keyup`) или по Ctrl+Пробел. Управление: ↑↓, → / ← раскрыть/свернуть, Enter или Tab — вставить, Esc. «код ↑ / смысл ↑» — что показывать первым. Вставка с «…» выделяет первое «…».

Что показывается, по приоритету:
1. **Внутри HTML-тега** (`<button |`) — его атрибуты из правил структуры: сначала обязательные, потом необязательные, «общие атрибуты» свёрнутой веткой. Вставка `type="…"` сразу показывает значения (`button`, `submit`, `reset`); булевы атрибуты — без значения. В кавычках значения — значения.
2. **В скобках вызова** (любой язык, кроме разметки и данных) — подпись `fetch(›url, options?)` (справка: Enter/Tab на ней работают как обычно); в кавычках аргумента — его значения (`addEventListener('` → click, input…); в Python необязательные — именованными (`encoding='…'`). **В CSS после `свойство:`** — значения свойства.
3. **Дерево вариантов** (`GET /api/variants`, `buildVariants`): корни — термины, у которых синоним совпал со смыслом («отступ» → margin, padding); латиницей — по началу имени. Под корнем — разновидности по имени (margin → margin-inline → margin-inline-start), конструкции словаря, до 3 кусков-примеров. Код корня — из шаблона «пишется», если он есть («картинка» → `<img src="…" alt="…">`, в пояснении «обязательно: src, alt»), иначе готовый вызов из словаря. Для русского запроса — ветка «куски из библиотеки» (слова запроса в начале слов названия; язык файла первым; для HTML подходят CSS и JS). Пусто в языке файла — другие языки по группам.
4. **Слова словаря по началу**, если дерева нет.

## 10. «что это?» (`sel-explain.js`)

Выделили код — рядом кнопка «что это?» (или Alt+Q; без выделения — текущая строка). Окно-схемка: над каждым узнанным куском скобка с подписью, под схемкой — лесенка связей и расшифровка.

- **Подпись:** синоним («внешний отступ»), иначе первая часть пояснения до «;»/«(» целиком. Смысл предка по имени (`margin-trim` → «внешний отступ») — только если у слова нет своего пояснения. Подписи раскладываются по рядам по реальной ширине, у правого края сдвигаются влево, пересчитываются при изменении размера окна.
- **Свои имена** (`POST /api/code/names` → `analyzeNames`, JS/TS и Python): что внутри («элемент страницы .save», «список: ['чай', 'кофе'] (2)»), пунктирная скобка, клик — к строке объявления.
- **Опечатки:** имя используется, нигде не объявлено и отличается от объявленного на 1 правку (на 2 у длинных) — «опечатка? → btn»; метод после точки, которого нет ни в словаре, ни в файле, но похожий на метод словаря — «addEventListener». В расшифровке «исправить» (во всём файле).
- **Связи** (раздел 13) — над скобкой словом («когда», «если», «куда»); запись `obj.prop =` всегда «куда»; своё имя с `[` — «откуда». **Лесенка** — что внутри чего по скобкам и отступам; в одной строке после «если/когда» — ступенью ниже.
- **Правила структуры** слова (раздел 12) — в расшифровке.

## 11. Проверки в редакторе (`code-marks.js`)

**Пока пишешь** (пауза 0,7 с), подсказка при наведении:
- незакрытые и лишние скобки, кавычки, комментарии — красным (`CodeCheck.scanBrackets`);
- опечатки имён — волнистым (`/api/code/names`);
- **раскладка** (`layout-check.js`, строки и комментарии не смотрятся, в HTML — только внутри тегов) — пунктиром: смесь латиницы и кириллицы в слове (`соnst`, `dщcument`), слово в русской раскладке, которое по клавишам известное (`сщтые` → const), своё русское имя в английской раскладке (`yfgbnrb` → напитки). Известные слова — словарь языка, ключевые слова, имена файла. У курсора кнопка «раскладка → const», Alt+Enter исправляет;
- **правила структуры** (`StructureRules.check`) — красным или пунктиром: вложенность и атрибуты HTML, «требует» и форма CSS, «внутри» / «после» и форма записи в коде (раздел 12).

**После «запустить»:** первая ошибка браузера или Python — красным то слово, на котором упало (из сообщения, ближе к столбцу ошибки), фон строки и под строкой плашка: что случилось по-русски и почему так обычно бывает (≈20 правил: not defined, reading of null/undefined, not a function, const, Unexpected token, missing ), NameError, IndentationError, KeyError, IndexError…). Для «не объявлено» — «может, btn?» и «исправить». Ошибка в другой вкладке — вкладка открывается; правка кода снимает отметку. В консоли место пишется как «app.js, строка 7».

**Tab после слова с шаблоном «пишется»** раскрывает шаблон с отступом строки; первое «…» выделено, следующий Tab — к следующему «…» шаблона. Нет шаблона — обычный отступ.

## 12. Правила структуры

**Файл** `public/dict/structure.json`: `{язык: [строки]}`, любой язык. Набор: HTML ≈660, CSS ≈70, JS ≈75, Python ≈55 (большая часть HTML дописана ИИ). **Модуль** `public/structure-rules.js` (`window.StructureRules`, `require` на сервере): `parse`, `merge`, `check`, `templateFor`, `attrsFor`, `describe`.

Строка — `слово: вид аргументы — пояснение`. Виды:

| Вид | Смысл | Пример |
|---|---|---|
| внутри / не внутри | где может / не может стоять (только если в другом месте это ошибка) | `li: внутри ul, ol` |
| содержит / не содержит | что внутри бывает / нельзя | `p: не содержит div, ul` |
| первым в | должен идти первым | `summary: первым в details` |
| после | идёт сразу после блока | `elif: после if, elif` |
| требует | без этого не сработает | `gap: требует display: flex | grid` |
| пишется | шаблон (`\n` — перенос, `…` — своё место) | `if: пишется if (…) {\n  …\n}` |
| обязательно / можно | атрибуты тега или параметры функции по порядку; `*: можно …` — общие атрибуты | `img: обязательно src` |
| значения | значения атрибута, параметра или свойства | `button[type]: значения button, submit, reset`, `display: значения block, flex, grid` |
| связывает / читает | связь по имени между файлами, `*` — имя | `data-*: читает js dataset.*, css [data-*]` |
| заметка | пояснение без проверки | `pre: заметка сохраняет пробелы` |

`слово: удалить` снимает все правила слова и значения его атрибутов (`img[…]`).

**Разбор терпит ответы ИИ:** синонимы видов (`ALIAS`: «только внутри», «не может содержать», «должен быть первым в», «идёт после», «нужно», «шаблон», «обязательные атрибуты», «необязательные», «допустимые значения», «применяется к»…), «:» в самом слове (`a:hover`, `::before`), пункты списков, нумерация, обратные кавычки (шаблон берётся из кавычек), «;» и точка в конце. Строка «слово: обычный текст» сохраняется заметкой. В файл правило ложится уже в своём виде.

**Описательные правила** (`inert`) сохраняются и показываются, но не проверяются: «внутри» с описанием вместо тегов («внутри потокового содержимого») или с обычными местами (body, div, main, section, li, td…) — это не ограничение; в остальных списках описательные пункты отбрасываются, имена в той же строке проверяются («a: не содержит a, button, другие интерактивные…» → a, button); «значения» с описанием не проверяются. В «разобрать» такие правила помечены.

**Дописывание** (`merge`, `POST /api/dict/structure`): повтор ничего не меняет («уже было»); «обязательно»/«можно» — новые пункты отдельной строкой; остальные списки — новые пункты в ту же строку; «пишется» и «требует» заменяются. Ничего не стирается, кроме «удалить» и «заменить все».

**Проверки по языкам:**
- **HTML/SVG** — стек тегов: внутри / не внутри / не содержит / первым в; незакрытые и закрытые не той парой теги; тег без обязательного атрибута; имя атрибута на одну правку от известного («tpye» → type); значение не из списка. `data-*`, `aria-*`, `on*` разрешены всегда.
- **CSS** — «требует» в том же правиле или в правиле с тем же селектором; свойство без «:», объявление без «;» перед следующим; значение-слово на одну правку от допустимого («relativ» → relative).
- **Код** — блоки по `{ }` (проход по символам: заголовок той же строки виден) или по отступам (Python): «внутри» — среди заголовков блоков вокруг есть нужное слово или знак («=>»); «после» — предыдущий блок того же уровня начинался с нужного слова. Форма из шаблона «пишется»: `if (…) {` → после if нужны круглые скобки; `if …:` (Python) → строка кончается «:».

**Форма** Опись → «правила структуры»: язык — выпадающий список (языки лаборатории и те, у кого есть правила, с числом правил; новый — «другой язык…» с проверкой на похожее имя); «показать текущие» по видам и слова словаря без правил (клик — заготовка в поле); «все в поле»; «разобрать» (что понято, что заметка, что нет — с текстом строки); «добавить»; «заменить все»; «промпт для ИИ» (формат, примеры, слова без правил; если словаря языка нет — ИИ берёт основные слова сам).

## 13. Связи слов (`public/code-links.js`)

Связь — свойство слова языка: **когда, если, иначе, для каждого, потом, при ошибке, откуда, куда, результат**. `relationOf(слово, язык, dict, пояснение)`:
1. правка пользователя — `dict/relations.json` (пустая — «связи нет»);
2. ядро языка — `CORE` в `code-links.js`, 10–30 ключевых слов на JS, Python, CSS, HTML (правится в коде);
3. начало пояснения словаря: «получить…» — откуда, «вывести…» — куда, «при клике…» — когда. В CSS/HTML по пояснению только когда / если / повтор / ошибка.

`depths(код, язык)` — вложенность по скобкам или отступам. Форма Опись → «связи слов»: сводка по языку, правки «слово: связь» (`нет`, `авто`), промпт для ИИ на неразобранные.

## 16. Безопасность

Сервер выполняет код (`/api/run`), пишет файлы (`/api/ws/*`) и пушит на GitHub (`/api/git/sync`), поэтому доступ — только со своей страницы:
- `listen(PORT, '127.0.0.1')`;
- для `/api/*` и `/vendor/*` проверяются `Host` и `Origin` (только localhost / 127.0.0.1 / [::1] на своём порту), иначе 403;
- изменяющие запросы CodeMirror требуют `X-Code-Lab: 1`;
- пути ограничены корнем (`within()`, `..`, ссылки наружу);
- ключи ИИ не пишутся в файлы.

Открыто: JSON-ответы отдают `Access-Control-Allow-Origin: *`. Не открывайте сервер в сеть и не пробрасывайте порт.

## 19. Ограничения и открытые пункты

- `Access-Control-Allow-Origin: *` (раздел 16).
- `/api/dedup` необратим без git.
- Описание обрезается до 400 знаков в `/api/edit` и `/api/ingest`; очередь ИИ пишет до 1200.
- Блоки по отступам и «:» в конце строки понимаются только для Python; языки с блоками через `end` (Ruby) и YAML правила «внутри/после» не проверяют.
- Ядро связей правится только в коде (`CORE`).
- Правила «связывает/читает» хранятся и показываются, но проверки «атрибут никто не читает» и «чем оформлено» по ним нет.
- Часть пояснений Python-словаря — на английском.
- При живом предпросмотре «запустить» отрабатывает дважды, и ошибка в консоли видна два раза.
- Заголовочный комментарий `code-lab-server.mjs` описывает старый формат.
