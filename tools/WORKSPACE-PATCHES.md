# Рабочая папка проекта — что добавлено и что менять в существующих файлах

Идея: **вся новая логика лежит в новых файлах**, а в ваших существующих — три крошечные вставки.
Так при слиянии с вашей параллельной версией конфликтовать почти нечему.

## Новые файлы (просто положить, ничего не сливать)

| файл | что это |
|---|---|
| `code-lab/lib/workspace.mjs` | сервер: папка проекта на диске, маршруты `/api/ws/*` |
| `code-lab/public/workspace.js` | панель «📂 проект», открытие/сохранение, Ctrl+S, файлы с компьютера |
| `code-lab/tests/workspace.test.mjs` | тест сервера (8 групп проверок) |
| `apply-workspace-patch.mjs` | вносит три вставки ниже сам |

## Три вставки в существующие файлы

Проще всего: `node tools/apply-workspace-patch.mjs` (сначала `--check`, чтобы увидеть, что будет сделано).
Он ищет места по якорям, а не по номерам строк, не дублирует при повторном запуске, сохраняет CRLF и кладёт копию `*.bak-workspace`.
Если не нашёл якорь в вашей версии — напишет, какое именно место, и вставьте руками:

**1. `code-lab-server.mjs`** — два места.

а) В конец блока `import …` вверху:
```js
import { handleWorkspace } from './code-lab/lib/workspace.mjs';
```
б) В обработчике запросов, **перед** первой веткой `if(u.pathname === '/api/template'…` (или любой другой `/api/…`):
```js
if(await handleWorkspace(req, res, u, { readBody, json, root: ROOT })) return;
```
Нужно, чтобы в этом месте были доступны `req`, `res`, `u` (разобранный URL), `readBody`, `json` и `ROOT`
(папка `code-lab`). Если у вас они называются иначе — поправьте имена в этой одной строке.

**2. `code-lab/public/sandbox.js`** — сразу после вызова `renderEds();` (тот, что перед блоком
«переключение режимов: визуал ↔ песочница», в самом конце файла внутри функции):
```js
window.codelabSandbox = {
  getFiles: () => files,
  setFiles: arr => { files = arr; save(); renderEds(); schedulePreview(); },
  refresh: () => { save(); renderEds(); schedulePreview(); }
};
```
Здесь `files`, `save`, `renderEds`, `schedulePreview` — существующие имена внутри `sandbox.js`.

**3. `code-lab/public/constructor.html`** — после строки со `sandbox.js`:
```html
<script src="/workspace.js"></script>
```

## От чего зависит `workspace.js` (смотрите сюда при будущей синхронизации)

Если вы меняете разметку песочницы в `sandbox.js`, эти имена должны остаться — иначе панель не найдёт, куда встать:
`#sandbox`, `.sb-bar`, `#sbAdd`, `#sbEds`, `.sb-ed`, `.sb-ed-head`, `.sb-name`, `.sb-lang`, `.sb-ed-del`, `.sb-code`, `.sb-run1`
и объект `window.codelabSandbox` с тремя методами выше. Объект файла в песочнице получает дополнительные поля
`path, mtime, eol, bom, sh` — они просто сохраняются вместе с остальными в `localStorage` (`codelab_sandbox`).

## Как пользоваться

1. Конструктор → 🧪 песочница → **📂 проект**. Слева появится дерево.
2. Нажмите на путь над деревом и вставьте полный путь к своей папке (`C:\проекты\сайт`). Выбор запоминается (`code-lab/workspace.json`).
   По умолчанию — папка `code-lab/workspace/`.
3. Клик по файлу открывает его в панели; первые открытые файлы заменяют три стартовых (index.html / style.css / script.js).
4. **Ctrl+S** — сохранить файл, в котором курсор; **💾** в заголовке — то же; **💾 все** — все изменённые. Оранжевая точка ● = не сохранено.
5. **⬆ файлы** или перетаскивание файлов в окно редакторов открывает файлы с компьютера в панелях без привязки к проекту;
   💾 у такого файла спросит имя и сохранит в проект.

## Что делает и чего не делает

* Работает только с выбранной папкой: `..`, абсолютные пути, `.git` и ссылки наружу отклоняются.
* Удаление — не насовсем: файл уходит в `.codelab-trash` внутри проекта.
* CRLF и BOM сохраняются (в редакторе текст с `\n`, на диск возвращается как был) — в git не появится «изменились все строки».
* Если файл изменили вне лаборатории после открытия — при сохранении спросит, перезаписывать ли.
* Файлы больше 2 МБ и двоичные не открываются.
* Сервер слушает только `127.0.0.1`. Не открывайте его в сеть: эта функция даёт запись в папку.
* Не сделано (осознанно, следующим этапом): открытие папки целиком одним действием из проводника (браузер не отдаёт путь),
  поиск по проекту, запуск проекта как единого целого (сейчас html/css/js собираются в превью как раньше, остальные языки запускаются по файлу).
